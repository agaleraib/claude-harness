### Why it's relevant

- **Dynamic Workflows** — emergent multi-subagent fan-out *inside a single Claude Code session*. Claude writes the orchestration script per-prompt; no pre-existing spec needed. - run on **ad-hoc prompts** (no spec required) — Claude writes the JS script on the fly;
- fan out **up to 1000 subagents** (vs. the harness's typical 2-5 parallel-when-safe tasks);

A future reader asks "do I still need the spec-driven `orchestrator` if I have Dynamic Workflows?" — the answer is yes, for the same reason 2026-05-10 §1 answered "yes, local `code-reviewer` is still useful": **different layer, different intent, different artifacts**. The orchestrator is the planned-work path; Dynamic Workflows is the emergent-work path.

## 4. Note the name collision between Claude Code's new `/goal` command and the harness's `today_goal.md`

The collision is **purely lexical**, but lexical collisions accumulate maintenance debt. A one-line "not to be confused with" inside `session-start`'s Step 8 (where `today_goal.md` is first introduced) is the smallest concrete intervention.
