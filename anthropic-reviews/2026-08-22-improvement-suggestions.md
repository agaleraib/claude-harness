## 3. Audit hard-rule prose in `CLAUDE.md` / skills against the "give judgment, not rules" and "stop compounding in CLAUDE.md" guidance from the Claude 5 context-engineering post

**scope: speculative**

**Source:** [The new rules of context engineering for Claude 5 generation models — Claude blog, 2026-07-24](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)

### Why it's relevant

The July 24 post frames six rewrites of previous best practices. The two with the most direct bite for this repo:

- **"Give judgment instead of rules."** The post's example — replacing "Default to writing no comments. Never write multi-paragraph docstrings…" with "Write code that reads like the surrounding code" — is verbatim the shape of guidance the harness's prompts still ship (search hits for "Never", "Always", "MUST", "must NOT" are dense across `CLAUDE.md`, `AGENTS.md`, and several `SKILL.md` files).
- **"Stop compounding in CLAUDE.md."** The post argues centralizing every known practice into `CLAUDE.md` is an anti-pattern once progressive-disclosure (skills, references/) is available. This repo already uses progressive disclosure well — SKILL bodies stay under 500 lines except for `close-wave` (675) and `planning-loop` (719), both of which lazy-load references — but `AGENTS.md` (131 lines) and the various inline don't-do lists inside SKILL.md files are worth an audit.

The audit is not "delete the rules" — it's "for each rule, is there a documented failure mode the model can't reason out of on its own? If yes, keep. If no, replace with a judgment-shaped statement." That framing is exactly what the July post asks for.

**Why defer.** Two independent reasons:

1. **Wrong generation.** The post's examples are calibrated for Claude 5. Trimming judgment out of prompts before the harness's model pin (§2) moves off Opus 4.7 risks removing guardrails Opus 4.7 still relies on. The 2026-04-23 postmortem is the cautionary tale — a 25-word verbosity cap removed one thing and knocked 3% off internal coding evals.
2. **Right-order dependency.** Land §2 first (the model pin moves). Then re-run this audit with Opus 5 as the operating point, so the "does this rule survive on this model" test uses the model the harness actually dispatches to.

### Concrete changes (once §2 lands)

For each file in `{CLAUDE.md, AGENTS.md, skills/*/SKILL.md}`:

- Enumerate every "Never / Always / MUST / DO NOT" line.
- For each, record the **specific failure mode** the rule guards against. If the failure mode is undocumented or the operator can't remember an instance, that's a rule that lived on legacy-generation capability — candidate for replacement with a judgment-shaped instruction (e.g. "Never write multi-paragraph docstrings" → "Comment only when the WHY is non-obvious").
- Keep the rules that guard against a documented, reproducible failure. That's the "you have a documented failure mode the model can't reason out of on its own" test from the post.
- Deliverable: one PR per file (so each is reviewable), a short prose note per removed rule explaining what evidence supports the removal, and a follow-up post-mortem entry if any rule turns out to have been load-bearing after all.

### Expected payoff

Fewer instruction conflicts for the model to adjudicate on every turn (the post's core diagnosis: "an unnecessary instruction is not free and neutral — it is a conflict the model has to adjudicate before it can start"). Reduces prompt-cache-invalidating churn from stale-rule edits.

**Verify before applying:** `grep -rn -E "Never |Always |MUST |DO NOT|must NOT" /home/user/claude-harness/CLAUDE.md /home/user/claude-harness/AGENTS.md /home/user/claude-harness/skills --include="*.md" | wc -l` — take a baseline count today; re-check after the audit lands to confirm the trend is downward. If it's already <30 across all three, the § is already substantively applied and can be dropped.

**Recommended verdict:** defer until §2 lands — the audit's test criterion (does the rule survive on this generation?) needs the harness pinned to Claude 5 first.
