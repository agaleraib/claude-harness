## 4. Adopt the Opus 5.5 post's one-hour cache lifetime + no-mid-session-model-switch cache-hygiene guidance

**Source:** [Coding sessions are longer and use more context. ## 5. Use Claude Code Artifacts to render wave receipts / session-end summaries as shareable artifacts

**Source:** [Claude Code now supports artifacts — claude.com/blog, 2026-06-18](https://claude.com/blog/artifacts-in-claude-code). Claude Code sessions can now produce **artifacts** — interactive web pages generated from session context (codebase + connectors + conversation) that auto-refresh as the session progresses. Beta for Team/Enterprise plans. Docs: [code.claude.com/docs/en/artifacts](https://code.claude.com/docs/en/artifacts).

### Why it's relevant

The harness has an existing "session-end artifact" pattern of its own:
- `skills/close-wave/SKILL.md` writes `docs/waves/<wave-N>-*receipt.md` — a text-based summary of what shipped.
- `skills/session-end/SKILL.md` writes `.harness-state/last_exit.md` — text-based cross-session handoff.
- `skills/project-tracker` (Second Brain remote) — text-based cross-session state.

Anthropic's Artifacts feature offers a **richer, interactive** version of the same surface: instead of a Markdown file, the session emits an interactive dashboard/checklist/timeline. For a solo repo, this doesn't obviously beat plain Markdown; for a shared repo with reviewers, it could replace the "walk me through what shipped" ritual.

### Why "defer", not "apply"

1. **Team/Enterprise beta only.** `.harness-profile` has `team.size: solo`. The harness is solo-maintained today (per this repo's `README.md` and `anthropic-reviews/README.md`), so the artifact-as-shareable-page target audience doesn't exist for this repo.
2. **Text receipts win for auditability.** `docs/waves/*receipt.md` is diffable, greppable, blame-annotated, and versioned in git. An artifact URL is a live-updated page — richer for humans, worse for `git log` archaeology. For a repo whose auditing surface is git history, the text file is the durable primitive.
3. **Cost surface is unclear.** Artifacts are billed against the session's token budget (they're generated from the session's context). For the harness's `xhigh`-effort loops, adding an artifact-generation step per wave has non-zero cost.
4. **Consumer projects might want this — but this file is about *this* repo.** A consumer project using the harness could adopt artifacts freely; that's not a change to the harness itself.

### Concrete change (deferred)

None this run. When/if the maintainer wants to take this on:

## 6. Adopt Anthropic's Test Impact Analysis (TIA) "keep state out of process" architectural insight

**Source:** [Agentic coding is straining CI. 4. **Wrong scale.** Anthropic's problem was 10× test volume growth × 8× Claude-authored code × 25× CI job surge over 6 months, hitting a singleton with millions of runs. The harness has an in-worktree test story running on the maintainer's machine.

### What this ISN'T rejecting

The post's other observations (Claude-authored code volume growth, PR-per-day count) are useful context for the harness's `stakes.level`/`effort_default` tuning conversation, but they don't call for a code change today. **Recommended verdict:** reject — the insight is real but the harness has no CI singleton to redesign; the failure mode presumes an infrastructure surface this repo doesn't have.
