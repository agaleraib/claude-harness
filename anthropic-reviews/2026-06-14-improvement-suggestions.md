## 1. Bookkeep Claude Fable 5 alongside the still-pending Opus 4.8 deferral

**Source:** [Claude Fable 5 and Claude Mythos 5 — anthropic.com/news, 2026-06-09](https://www.anthropic.com/news/claude-fable-5-mythos-5). Key facts:

- First **generally-available Mythos-class** model. The class sits *above* Opus in Anthropic's tier ordering.
- API model id: `claude-fable-5`. Pricing: **\$10 input / \$50 output per MTok** (Batch API \$5/\$25). 1M context, 128K max output, always-on adaptive thinking.
- "State-of-the-art on nearly all tested benchmarks of AI capability, showing exceptional performance in software engineering, knowledge work, vision, scientific research, and many other areas."
- **Safety fallback:** in high-risk domains (cybersecurity, biology, chemistry, model distillation) Fable 5 blocks the response and falls back to **Opus 4.8**. So for a coding harness the practical question is "Fable 5 *and* Opus 4.8 vs Opus 4.8 alone."
- Companion: Claude Mythos 5 stays invitation-only under Project Glasswing — not user-installable.

### Why this is a bookkeeping row, not a fresh §

The model-pin question is already open. PR `claude/anthropic-review-2026-06-08` §1 deferred the **Opus 4.7 → 4.8** bump until 4.8 has ≥30 days of postmortem-stable shipping-default behavior. Fable 5 is **two pricing tiers above** that deferred decision and ships ~12 days after Opus 4.8. The harness pins `model.primary: claude-opus-4-7` (`.harness-profile:30`) and `model.fallback: claude-sonnet-4-6` (`.harness-profile:31`); there is currently **no Mythos-class slot** in the pin schema, by design — the harness's pin contract is "primary + fallback," not "best-available + cost-tier."

So the right call today is to note that Fable 5 GA happened, append a row to the parking spot 2026-06-08 §1 already opened, and *not* file a fresh edit. Acting on Opus 4.8 first (when 2026-06-08 §1's trigger fires) closes the more relevant decision; Fable 5 is the second cut.

### Why pricing matters more than capability here

This harness is solo-maintained on a Pro/Max-class plan (per `.harness-profile:audience.size_estimate: "1"` + `team.size: solo` mentioned in CLAUDE.md). Fable 5 at **\$10/\$50 per MTok** is 2× the input cost of Opus 4.8 (\$5/\$25). For the harness's workload — `code-reviewer` on every commit, `/run-wave` cycles, the orchestrator dispatching subagents — that 2× compounds. The Fable 5 launch post itself frames the model as "demanding reasoning, long-horizon agentic work, coding, knowledge work, vision, and large-context analysis," but a single solo coding harness rarely hits the long-horizon ceiling that justifies the premium. Opus 4.8 covers the coding bar at lower marginal cost.

Independent benchmark signal: Fable 5 falls back to Opus 4.8 on the cyber-defensive prompts that are the most common *coding-harness* concern (vulnerability triage, security review). So even if the harness used Fable 5 for `code-reviewer`, the *security-review* subset of that workload would still execute on Opus 4.8 — paying Fable 5 prices for Opus 4.8 outputs.

## 2. Bookkeep nested sub-agents + `post-session` hook + `disableBundledSkills` alongside the dynamic-workflows deferral

**Source:** [Claude Code changelog 2.1.169 → 2.1.176](https://code.claude.com/docs/en/changelog), released 2026-06-08 through 2026-06-12. Three items relevant to the harness:

- **Nested sub-agents up to 5 levels deep** (v2.1.172, 2026-06-10): sub-agents can now spawn sub-agents, capped at 5 levels. Previously the orchestrator pattern was strictly two-layer (parent + one tier of subagents). This is the static-orchestrator equivalent of dynamic workflows' fan-out, without the research-preview gating dynamic workflows still has.
- **`post-session` lifecycle hook** (v2.1.169, 2026-06-08): a first-party hook that fires at session end, intended for self-hosted runners (snapshot work, export logs). Conceptually adjacent to the harness's `skills/session-end/SKILL.md` ritual + `.harness-state/last_exit.md`.
- **`disableBundledSkills` setting + env var** (v2.1.169, 2026-06-08): hides Anthropic-bundled skills and slash commands (e.g. `/code-review`, `/simplify`, `/verify`, `/run`, `/init`, `claude-api`, `deep-research`, `update-config`, `keybindings-help`, `fewer-permission-prompts`, `loop`, `security-review`). The available-skills list in this session shows 13 bundled skills — non-trivial context contribution.

### Why this is a bookkeeping row, not a fresh §

PR `claude/anthropic-review-2026-06-08` §2 deferred the dynamic-workflows positioning paragraph until either dynamic workflows leave research preview *or* the maintainer hits a class of task the static methodology demonstrably can't structure. All three items above land in the same parking spot:

- **Nested sub-agents** is the lighter-weight cousin of dynamic workflows. The orchestrator (`.claude/agents/orchestrator.md`) doesn't currently recurse — and there's no concrete task in the wave registry today where 3+ levels of dispatch is the bottleneck. Bookkeep until there is one.
- **`post-session` hook** is a first-party version of the harness's `session-end` skill. The harness's version is invoked manually (`session-end` is a slash command, not a hook), runs the project-tracker agent, writes `last_exit.md`, etc. The first-party hook fires automatically. The two are not exclusive — you could wire `session-end`'s script into the `post-session` hook to make it automatic — but doing so today would lose the `AskUserQuestion` step in `skills/session-end/SKILL.md` that the manual flow uses. Defer until automation is wanted.
- **`disableBundledSkills`** is a relevant knob *if* the harness ever measures bundled-skill context cost and finds it exceeds a budget. The harness already audits its own skill budget (`2026-05-07` tracker row: "audit 2026-05-07: ~6.1K of ~15.5K skills budget used"); adding bundled skills on top could blow that budget, but there's no measurement today proving it. Defer until measured.

### Concrete change (deferred — do not apply now)

If/when the maintainer wants to act on any of the three, the highest-leverage of the three is `disableBundledSkills` — it's a single setting that may or may not be worth flipping based on a measurement.

```diff

+   "disableBundledSkills": true

```

Or equivalently set `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1` in the environment. But: this hides skills that may be genuinely useful (`/code-review`, `claude-api`, `verify`) — the right answer is probably **selectively** rather than wholesale, but the setting is boolean. If it stays boolean, the suggestion is "leave default-on" until/unless context-budget pressure is measured.

For the `post-session` hook: the migration cost is "rewrite `skills/session-end/SKILL.md`'s steps as a hook script." That's a non-trivial refactor that loses the interactive `AskUserQuestion` step. Don't act until automation is the explicit goal.

For nested sub-agents: the harness's orchestrator dispatch table (`.claude/agents/orchestrator.md`) would need to grow a "this subagent can dispatch further" affordance. Today the table is flat. Don't act until a wave needs it.
