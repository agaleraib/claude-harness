## 1. HTML-over-Markdown for ephemeral human-facing reports (not for version-controlled artifacts)

**Source:** [Using Claude Code: The unreasonable effectiveness of HTML — claude.com/blog (Thariq Shihipar, Claude Code eng lead, early–mid May 2026)](https://claude.com/blog/using-claude-code-the-unreasonable-effectiveness-of-html). Thesis: Markdown becomes hard to read past ~100 lines; HTML lets Claude organize structure visually (tabs, diagrams, links, mobile-responsive layout) and add interactivity (sliders/knobs, copy-to-prompt). Prompt is as simple as "make an HTML file / artifact." (Date is ambiguous across syndication — Simon Willison covered it 2026-05-08, some republishes stamp 2026-05-20; it was not in the 2026-05-10 run's window, hence reviewed now.)

### Why it's relevant
The harness has a `SendUserFile` tool available (surfaced in the Claude Code system prompt for this environment as the channel for "the file *is* the deliverable — a generated diagram, a report, a screenshot"). Thariq's post is the canonical argument for what *format* such a delivered file should take when the audience is a human reading it once, not a diff reviewer.

### Why it's `defer`, not `apply`
The CHECK-FIRST grep is decisive here:

- `grep -ril "html" skills/ docs/ AGENTS.md` → the **only** hit is one spec filename (`docs/specs/2026-05-13-memory-system-redesign-migration.md`), not an output-format convention.
- `grep -ril "SendUserFile" skills/ docs/ AGENTS.md` → **zero hits.** No skill in this repo currently emits a `SendUserFile` deliverable at all.

So the insight has **no call site**. Every human-facing artifact the harness produces today is *version-controlled Markdown by deliberate design*:
- `anthropic-reviews/<date>-improvement-suggestions.md` — must stay Markdown for `git diff` + PR triage (the whole routine depends on diffable history).
- `docs/specs/*.md`, `docs/plan.md` — diffable specs/plans.
- `.harness-state/*.md` (`last_exit.md`, `today_goal.md`, `parking_lot.md`) — cross-session memory, read by `session-start`.

HTML would actively *hurt* all of these (binary-ish diffs, no line-level review). Thariq's own framing agrees: HTML wins for *artifacts you read*, not *artifacts you version and review*. Adding an HTML guardrail now would be a convention with nothing to govern.

### Concrete change (deferred — do NOT apply this run)
When/if a harness skill is built whose deliverable is an ephemeral, human-facing report or visualization (e.g. a one-shot dependency-graph view, a `/harness-status` rich dashboard surfaced to the user, an audit summary), add a single sentence to that skill's `SKILL.md` and/or `AGENTS.md`:

```diff
+ ## Output format for user-facing deliverables
+ For a one-shot artifact a human reads (a report, diagram, or dashboard) and that
+ is NOT committed to version control, prefer a single self-contained HTML file
+ delivered via SendUserFile over Markdown — HTML carries richer structure (tabs,
+ diagrams, links) and stays readable past ~100 lines. For anything version-controlled
+ and reviewed via diff (specs, plans, triage docs, .harness-state/*), keep Markdown.
```

The distinction — *ephemeral & read* → HTML; *versioned & reviewed* → Markdown — is the durable takeaway worth parking now even though there's no place to write it yet.

### Expected payoff (when applied)
The first time someone builds a report-emitting skill, the format decision is already made and won't default to a 300-line unreadable Markdown blob.

**Verify before applying:**
1. `grep -ril "SendUserFile" /home/user/claude-harness/skills` — if this is **still zero**, there is no call site and this § stays deferred. The day it returns a hit (a skill emits a user file), revisit.
2. `grep -ril "html" /home/user/claude-harness/skills` — confirm no skill has already adopted an HTML-output convention (today only a spec *filename* matches, not a convention).
3. Re-confirm the source URL resolves and the post still recommends HTML *for read-once artifacts* (not as a blanket Markdown replacement) before quoting it — the nuance is what keeps this from over-reaching onto the harness's diffable Markdown.

**Recommended verdict:** defer until a harness skill emits ephemeral human-facing reports — genuine methodology insight (`scope: speculative`), but no call site today and the harness's committed artifacts must stay diff-friendly Markdown.
