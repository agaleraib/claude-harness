## 1. Cite "The new rules of context engineering for Claude 5" in `AGENTS.md`; schedule a prune pass over prescriptive rule text

## 4. Consider extracting the harness's implicit verify-gate into a discrete `/verify` skill, parallel to Anthropic's newly-bundled `/verify`

**Source:** [Building verification loops in Claude Code with skills — claude.com/blog, ~2026-07-22](https://claude.com/blog/building-verification-loops-in-claude-code-with-skills). Anthropic describes a chain-of-skills pattern where `/code-review` finds bugs, `/simplify` cleans up, and a new bundled `/verify` skill builds, runs, and observes the app for deterministic signals (linter / type-checker / test output) — with the pattern that "one skill always runs another when it finishes" (e.g. `/simplify` chains to `/verify`).

### Why it's relevant
The harness has essentially the same verification loop already — but embedded inside `run-loop`'s per-item mechanical gate (`skills/_shared/loop/protocol/gate.ts`, `verify-gate.test.ts`, etc.) rather than exposed as a standalone user-invocable skill. It is:

- Not user-invocable outside `/run-loop`
- Not chainable from other skills (the harness's `/commit` skill runs `code-reviewer` but doesn't run a discrete verify step)
- Not documented as its own primitive

Anthropic just standardised the naming (`/verify`) and the chaining pattern. Two questions worth asking the maintainer:

1. **Would extracting `/verify` as a discrete skill pay off** — i.e. would `/commit` benefit from a `/verify` step post-review, and would consumer projects want to run `/verify` manually outside `run-loop`?
2. **If yes, does the harness `/verify` piggyback on the loop's existing `GateRunner` seam** (so both call the same code path) or diverge?

This is genuinely a design question, not a rewrite — the answer might well be "the loop is the only sensible caller; leave it embedded." But the maintainer should decide, not have the question stay implicit.

### Concrete change
No code edit this §. This is a park-and-decide:

- **If defer:** add a two-line note to `parking_lot.md` under a new "Verification skill extraction" bullet, linking this §.
- **If apply:** spec via `/spec-planner`. The spec should cover: (a) whether `/verify` becomes a first-class user-invocable skill, (b) whether `/commit` chains to it, (c) whether consumer projects installing the harness get `/verify` in their skill list, and (d) the seam contract with `skills/_shared/loop/protocol/gate.ts` (so both callers exercise the same verification path).

### Expected payoff (if applied)
- Vocabulary + slash-command alignment with Anthropic's bundled `/verify` — users who install the harness on top of a stock Claude Code install get the same chained pattern.
- `/commit` becomes stronger — post-review verify catches "review passed but the change actually broke the build" cases the current flow relies on the human noticing.

### Cost (if applied)
- Non-trivial spec: needs to reconcile the loop's gate with a user-invocable skill without duplicating the check code. Not a `/micro`.
