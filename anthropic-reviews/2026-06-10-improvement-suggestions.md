## 2. Add one README paragraph naming Anthropic's Dynamic Workflows ("a harness for every task") and how it differs from this repo's harness

**Source:** [A harness for every task: dynamic workflows in Claude Code — claude.com/blog, 2026-05-28](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code) — the title is the leverage. ### Why it's relevant
The Anthropic post defines a *harness* as "the system around the model that decides how work gets split, which subagents spawn, what tools each one gets, how their output is verified, which model handles which step, how work is isolated, and when the job is actually done" — and then says *Claude now writes one on the fly, custom-built for the task at hand*. This is the same vocabulary the repo uses, and it's the closest Anthropic has come to publishing a competing surface.

This § is the **harness-vs-harness** version of the 2026-05-10 §1 framing (which positioned `code-reviewer` vs. `/ultrareview`). Same shape: name the overlap, draw the boundary, tell the future reader where each one fits. Today there is **zero mention of "Dynamic Workflows" or "ultracode" in this repo** (`grep -rn "dynamic workflows\|ultracode\|a-harness-for-every-task" .` returns nothing — verified during this run).

The boundary is concrete:

- **This repo's harness** is *opinionated structure*: `.harness-profile`, `criteria/`, `agents/`, `skills/`, `docs/plan.md`, `.harness-state/` — the artifacts and conventions a *human* uses across many sessions on a project, distributed via `setup-harness`.
- **Dynamic Workflows** are *ephemeral orchestration scripts*: Claude writes a JavaScript file at runtime that fans out dozens-to-hundreds of subagents in a single session, scoped to one task.

They are at **different altitudes**, and they *compose*: a user with this repo installed could fire `ultracode` inside a session, and the dynamic-workflow script Claude writes would still see `.harness-profile`, the agents in `.claude/agents/`, and the project's `criteria/`. The repo's harness is the durable scaffolding; dynamic workflows are an in-session multiplier.
