## 1. Cross-reference Agent View as a hands-off invocation path for existing harness skills

**Source:** [Agent view in Claude Code — claude.com/blog, 2026-05-11](https://claude.com/blog/agent-view-in-claude-code) (companion docs: [Manage multiple agents with agent view — code.claude.com/docs/en/agent-view](https://code.claude.com/docs/en/agent-view)). Claude Code v2.1.139+ ships Agent View — `claude agents` opens a dashboard of every background session; `claude --bg "<task>"` starts a fresh background session from the shell; `/bg` backgrounds the current session. Subagents launched *from inside* a session "aren't listed as separate rows" — so the harness's orchestrator-dispatched subagents do not collide with Agent View's session table. Background sessions auto-isolate file edits under `.claude/worktrees/`.

### Why it's relevant
The harness ships ~18 skills (the recurring ones include `/apply-anthropic-reviews`, `/planning-loop`, `/run-wave`, `/close-wave`, `/triage-parking`, `/harness-status`, `/session-start`, `/session-end`). The Agent View post explicitly states:

> Packaging a recurring task as a skill lets you start the same workflow from agent view repeatedly without retyping the prompt.

That sentence describes the harness's existing shape. Concretely, after upgrading to Claude Code v2.1.139+, the maintainer can already do:

```bash
claude --bg "/apply-anthropic-reviews"       # this very routine, hands-off
claude --bg "/planning-loop"                 # planner continuation in background
claude --bg "/run-wave"                      # wave runner in background
claude --bg --agent code-reviewer "<task>"   # code-reviewer agent in background
```

…without any harness change. The skill-as-dispatchable-entry-point property emerges from how Claude Code resolves `/<skill-name>` in the dispatch input. The harness is already correctly factored.

Two adjacent facts to confirm before claiming "no harness change ever":

1. **`.claude/worktrees/` is already gitignored.** `.gitignore:58` literally reads `.claude/worktrees/`. So a background session that edits files inside this repo from Agent View will not leak its isolated worktree into git. ✓ Already in place.
2. **Subagents launched from inside an Agent View-dispatched session "aren't listed as separate rows"** (per the docs). The orchestrator agent (`.claude/agents/orchestrator.md`) dispatches subagents with `isolation: "worktree"` per the runtime-orchestrator spec (`docs/specs/2026-04-12-runtime-orchestrator.md:74`). Those subagent worktrees and the Agent View per-session worktrees are both rooted under `.claude/worktrees/` and both already gitignored. ✓ No collision.

  ```markdown
  Every skill in `~/.claude/skills/` is dispatchable as its own background session via Claude Code's Agent View (v2.1.139+):

  - `claude --bg "/<skill-name>"` from the shell, or
  - `/<skill-name>` typed into the `claude agents` dispatch input.

  Subagents dispatched from inside a session (e.g. by `orchestrator`) do not appear in Agent View — they run inside their parent session's row, isolated under `.claude/worktrees/` (already in `.gitignore:58`).
  ```

### Why this is `defer`, not `apply`

1. **Premature for the maintainer's current workflow.** The maintainer runs these skills manually today and has not (per `parking_lot.md` and the tracker) expressed friction with that. A documentation edit that pre-announces a workflow nobody is using yet is the kind of thing the harness's "Why Not Superpowers" framing in `README.md` actively cautions against — adding inert context that future readers wade through.
2. **Same parking spot as `2026-05-10 §2`.** That § flagged Cloud Routines as the candidate platform for migrating the anthropic-reviews routine itself, and was deferred. Agent View is the *interactive*-dispatch sibling of Cloud Routines (cloud sessions are scheduled and unattended; agent-view sessions are local and unattended). If/when the maintainer reaches for either, they'd want both documented together, not piecemeal.
3. **Risk of stale documentation.** Agent View is still labeled "research preview" in the docs (`Agent view is in research preview and requires Claude Code v2.1.139 or later. … The interface and keyboard shortcuts may change as the feature evolves.`). Pinning the harness's docs to research-preview ergonomics commits the maintainer to chasing changes.
4. **The corroboration value is the main payoff, and that's already captured here.** Future readers of this tracker entry will see that Anthropic's Agent View post validates the harness's "every routine is a skill" packaging decision. That's the durable record; the doc edit is optional.
