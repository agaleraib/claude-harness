## 2. Cite *The components of agent memory* as the research anchor for the harness's existing 4-layer memory shape

**Source:** [The components of agent memory — anthropic.com/research, 2026-11-06](https://www.anthropic.com/research/components-of-agent-memory)

### Why it's relevant

The post gives the **first first-party taxonomy** of agent memory as a layered store, and the four layers map almost 1:1 onto the harness's existing memory artifacts:

| Anthropic layer (2026-11-06) | Harness artifact |
|------------------------------|------------------|
| 1. **Transcripts** (searchable event log) | `.harness-state/` per-session logs + Claude Code's `~/.claude/projects/<cwd>/` transcripts |
| 2. **Memory notes** (salient observations) | `parking_lot.md`, `last_exit.md`, `today_goal.md`, `current_micro.md` |
| 3. **Memory representations** (derived structures) | `~/.claude/memory/feedback/FEEDBACK.md` index + per-pattern files |
| 4. **Injected context** (loaded into every session) | `MEMORY.md` auto-write + `CLAUDE.md` + session-start skill output |

The post's three findings that **validate the harness's existing design** are worth citing as durable anchors:

1. *"it helps to tell Claude what memory is for, but not how to use it. Fixed rules like 'record only failures' hurt stronger models."* — vindicates the harness's **non-prescriptive** session-end ritual (asks "how did today go?" rather than imposing a schema).
2. *"the top layer of the memory hierarchy has to stay relatively small."* — vindicates the harness's **per-cwd `MEMORY.md` + manual promotion** gate.
3. *"Parallel agents writing one shared file overwrote each other. One page per entity fixed it."* — vindicates the harness's **per-pattern** files under `~/.claude/memory/feedback/<slug>.md` (`AGENTS.md:65, 77`).

The one post finding that **implies a future action** is:

> *"the dreaming model promotes automatically […] Dreaming reads the layers below and writes to the layers above. It corrects wrong notes, creates notes, builds wikis, merges duplicates, and promotes material to injected context."*

The harness does this manually via the maintainer-run `/memory-prune` skill and the `session-end` ritual. The post describes a scheduled automated version. For a solo harness, manual promotion is **a deliberate safeguard** (preserving per-cwd provenance per `CLAUDE.md:11`), not a gap — but it's worth a durable note that if the maintainer ever adds a scheduled dreaming pass, the post is the design anchor.

This continues the deferred chain: **2026-04-19 §2** (brain/hands) → **2026-04-25** (Managed Agents memory skip) → **2026-05-07 §1** (dreaming in Managed Agents) → **2026-05-10 §3** (dreaming as bookkeeping). The 2026-11-06 post is the **first non-Managed-Agents research anchor** in that chain — it generalizes the pattern beyond the Managed Agents product.
