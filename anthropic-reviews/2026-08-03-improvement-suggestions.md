## 1. Add the "CLAUDE.md is for facts; skills are for procedures" framing to the setup-harness template + README

**Source:** [Steering Claude Code: when to use CLAUDE.md, skills, hooks, and subagents — claude.com/blog, 2026-06-18](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more). Anthropic's canonical decision framework for the seven Claude Code instruction methods: **CLAUDE.md files, rules, skills, subagents, hooks, output styles, and appending the system prompt.** Each one is scored on three axes: (1) when the instruction loads into context, (2) what happens to it during compaction, (3) what it costs in tokens. Two of the post's crispest heuristics:

- **"CLAUDE.md is for facts; skills are for procedures."**
- **"Does this instruction need to survive context compaction? If yes, use CLAUDE.md or Skills (they reload). Must it override everything else, with no exceptions? Use system-prompt appending."**

### Why it's relevant
The harness has **strong opinions** on this exact split — CLAUDE.md carries build/test commands + non-obvious conventions (per `setup-harness` Step 4), skills are the workflow verbs (`/commit`, `/run-loop`, `/deploy-check`, etc.), and hooks are the deterministic guardrails (the `/run-loop` catastrophic-command denylist). But the framing is **implicit** — no single file in the repo states the rule Anthropic has now made canonical. Grep confirms:

```

$ grep -rn "steering-claude-code\|Steering Claude Code" /home/user/claude-harness → 0 hits
```

The `setup-harness` templates (`templates/user-CLAUDE.md`, plus the project-level CLAUDE.md skeleton in Step 4) are the primary vector by which future consumer projects inherit the harness's mental model. Adding the one-line rule at the top of the template — and citing the source in the README — costs almost nothing and closes a doc gap the next time a consumer-project maintainer asks "why is X in a skill and Y in CLAUDE.md?"

+## When to use CLAUDE.md vs skills vs hooks vs subagents
+> Canonical rule from Anthropic ([Steering Claude Code, 2026-06-18](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)): **CLAUDE.md is for facts; skills are for procedures.** Skills' name/description load at session start and stay across compaction; the body only loads when invoked. **Source:** [How we contain Claude across products — anthropic.com/engineering, 2026-05-25](https://www.anthropic.com/engineering/how-we-contain-claude). The post documents Anthropic's **three-layer defense** for their own agentic products (claude.ai, Claude Code, Claude Cowork):

1. **Hardware isolation** — sandboxes / VMs constrain what an agent can touch on the host.
2. **Probabilistic model controls** — training + system-prompt guardrails against known misuse patterns.
3. **Content-access restrictions** — programmatic hooks that gate specific operations.

The post is notably candid: it discloses a **February 2026 internal red-team exercise where Claude Code was phished into exfiltrating AWS credentials 24 of 25 times** through a malicious prompt — the exact failure mode the harness's denylist hook is designed to catch at the tool-invocation layer.
