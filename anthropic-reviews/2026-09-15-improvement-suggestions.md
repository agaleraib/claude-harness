## 2. Cite "Building agents with the Claude Agent SDK" (gather → act → verify → repeat) as the canonical loop framing

**Source:** [Building agents with the Claude Agent SDK — Anthropic Engineering, 2026](https://www.anthropic.com/engineering/building-agents-with-the-claude-agent-sdk) — the SDK's canonical loop is *"gather context → take action → verify work → repeat"*, and the developer sees and controls the agent loop directly rather than routing through abstraction layers.

### Why it's relevant
`.claude/agents/orchestrator.md` already implements exactly this loop across Steps 2 (parse spec = gather context), 5 (dispatch = take action), 6 (verify), and 7 (commit; loop resumes at Step 5 for the next task). Today the doc names those steps mechanically — "Step 6: Verify" — but never names the pattern. Anthropic's Agent SDK post codifies the same four-step shape and calls it the *"cycle you design, not the prompt"*. Naming the alignment (a) makes the orchestrator's structure legible to anyone who has read Anthropic's post and (b) inoculates the harness against the "why don't you use the SDK?" question — the answer is *"the harness IS this loop, just factored through Claude Code's session model instead of `@anthropic-ai/claude-agent-sdk`"*.

This is not a claim to *use* the Claude Agent SDK — the harness's execution model is Claude Code + Skills + subagents, not the SDK's Python/TS library. It is a claim about *pattern equivalence*.
