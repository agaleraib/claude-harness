## 2. Cite "Components of agent memory" in README references and add a MEMORY.md 25 KB / 200-line load-cap guardrail

**Source:** [The components of agent memory — anthropic.com/research, 2026-11-06](https://www.anthropic.com/research/components-of-agent-memory).

### Why it's relevant

The post establishes the clearest first-party memory-architecture taxonomy Anthropic has published since Managed Agents. The layers, bottom-up:

1. **Transcripts** — searchable event log of past sessions.
2. **Memory notes** — short summaries Claude writes when something is clearly worth remembering.
3. **Memory representations** — wikis built from those notes (longer-form curated knowledge).
4. **Injected context** — content loaded into every session (e.g. MEMORY.md).

"Dreaming" is an offline process that reviews transcripts and reorganizes layers 2–3. Weight changes, in-context learning, and compaction are **excluded** from the definition.

The harness already implements this pattern manually with the user in the loop:

- `.harness-state/` — receipts and logs (≈ transcripts, machine-readable).
- `last_exit.md`, `parking_lot.md`, `today_goal.md`, `current_micro.md` — Claude-written notes (≈ memory notes).
- `~/.claude/memory/USER.md` + per-cwd `MEMORY.md` + `~/.claude/memory/feedback/` — curated representations (promoted manually per `AGENTS.md ## Memory`).
- `CLAUDE.md` + `AGENTS.md` + `~/.claude/skills/*/SKILL.md` — injected context loaded every session.
- `session-end` + `memory-prune` — manual "dreaming" (user is the curator).

This is one of the cleanest conceptual validations we've gotten that the harness's memory-loop is on-vector with Anthropic's own thinking. Worth a reference citation + a specific guardrail.

### Concrete change

The post says: *"Claude Code loads only the first 200 lines or 25 KB of MEMORY.md."* If the harness's `session-end` ritual or `memory-prune` skill writes past that cap, the tail silently disappears from future sessions.

The harness has two places this matters:

The harness's deferred 2026-04-19 §2 / 2026-05-10 §3 already parks "automated dreaming" behind Managed Agents adoption; this is one more datapoint for that parking spot, not a trigger to promote.

### Expected payoff

## 6. Adopt "Redesigning source control at Anthropic" (Scion / Antique) patterns in the harness's git workflow

**Source:** [Redesigning source control at Anthropic — anthropic.com/research, 2026-10-13](https://www.anthropic.com/research/redesigning-source-control).

### Why it's relevant (and why it still gets a `reject`)

Anthropic spent five months replacing git with an in-house VCS called **Scion** for their monorepo, plus **Antique** (code review) and source-control IAM. The post describes the problems that drove the redesign (branch-ref proliferation, full-checkout latency, path-level permissions at scale) and some generalizable patterns:

- **Long-lived branches limited to `main` + release branches** — all other branches are short-lived topic branches.
- **No `git push` to the server** — commits are made server-side via a Scion API.
- **Sparse / virtualized checkouts** so CI reads only what it needs.
- **Automated tests run after merge, before deploy** — a merge queue becomes a bottleneck at high merge rates.
- **Reviewers check intent, not every line** — Antique surfaces intent-level summaries.
