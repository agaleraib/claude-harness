## 5. Chain `/simplify` (optionally `/verify`) into `/commit` per the **"Building verification loops"** playbook

**Source:** [Building verification loops in Claude Code with skills — claude.com/blog, 2026-07-22](https://claude.com/blog/building-verification-loops-in-claude-code-with-skills). The Claude Code team's own day-to-day pattern: `/code-review` finds bugs → `/simplify` cleans up the diff → `/verify` confirms end-to-end behavior → optional `/design` if UI changed. The chaining rule that turns habit into contract: **"/simplify always runs /verify when it finishes."**

### Why it's relevant
The harness ships **both** ends of that pattern separately:
- `skills/commit/SKILL.md` **Step 3** invokes the `code-reviewer` agent on the staged diff.
- `skills/simplify` (bundled as an Anthropic skill in this session — visible in the available-skills list) applies simplification passes.
- `skills/code-review` (also bundled Anthropic) is the pre-`/commit` review skill separate from the `code-reviewer` agent.

What the harness doesn't do today: **chain** them. `skills/commit/SKILL.md` ends Step 3 with `code-reviewer`'s findings, jumps to Step 4 handling those findings, and does not call `/simplify` before or after. The Anthropic playbook says the pain of "I always run /simplify after /code-review manually" is exactly the pain that chaining is designed to fix.

### Why `defer`, not `apply`
1. **The habit path works today.** The maintainer can invoke `/simplify` between Step 3 and Step 5 manually. There's no evidence the manual habit is failing to fire; that's the trigger the playbook describes for adopting the chain.
2. **Chaining is a workflow-contract change.** Adding `/simplify` to `/commit`'s middle steps means every commit now runs at least two skills instead of one. That's a token-cost multiplier (small — both skills are fast) and a wall-clock cost (medium — `/simplify` can propose non-trivial diffs). The maintainer should decide whether that shape is what `/commit` should be.
3. **The bundled skills may not be right for this repo.** Both `/simplify` and `/code-review` are Anthropic-authored generalists. The harness's `code-reviewer` **agent** already integrates the local `criteria/` rubrics, which the generalist skill does not. Chaining the wrong tool would be a regression.
4. **Speculative for solo tooling.** The routine's `apply / defer / reject / spec` rubric names "speculative for solo tooling" as a defer indicator (not a reject) — flag the pattern for the maintainer, don't kill it.

### Concrete change (deferred)
If picked up later, the smallest safe experiment:
- Add a new **Step 4a** to `skills/commit/SKILL.md`, gated on the review-findings outcome: "if `code-reviewer` reported zero blocking findings, run `/simplify` on the staged diff; present its proposals numbered under an `AskUserQuestion` gate before applying."
- Do **not** chain `/verify` in the first cut — the harness's build/test story is repo-specific (per `.harness-profile.gate.tests`); autoloading `/verify` would over-fit to some repos and no-op on others.
- If the chain proves useful, promote it from `AskUserQuestion`-gated to auto-run behind a `.harness-profile` opt-in (`commit.chain_simplify: true`).

### Expected payoff (when applied)
The end-of-task diff is smaller and cleaner **before** the commit lands, without the maintainer having to remember. Cheap simplifications (duplicate constants, extractable one-shots, dead branches) get caught inside the same session context that just wrote the code, rather than in a follow-up cleanup that has to re-learn what changed.

**Verify before applying:**
1. `grep -n "Step 4a\|/simplify\|simplify\.md" skills/commit/SKILL.md` — must return zero relevant hits (only the `criteria/code-simplicity.md:70` reference to `/simplify` should exist elsewhere). If Step 4a is already there, this § is stale.
2. Confirm the bundled Anthropic `/simplify` skill hasn't been superseded by a repo-local skill in this harness's `skills/` tree at apply time.
3. Confirm the manual `/simplify`-after-`/commit` habit is actually failing to fire (i.e., review parking-lot notes or a session where a simplifiable diff got shipped without the pass). If there's no signal, the defer stands.

**Recommended verdict:** defer until pain surfaces — the chain is a real Anthropic-blessed pattern but the harness lacks evidence that the manual path is dropping the ball, and the mechanism swap (skill chain vs manual invoke) has a workflow-contract cost.
**Status:** PENDING — awaiting triage in PR review
