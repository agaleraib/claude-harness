## 2. Cite *How we contain Claude across products* as fresh first-party evidence under README "Why Not Superpowers"

**Source:** [How we contain Claude across products — Anthropic Engineering, 2026-05-25](https://www.anthropic.com/engineering/how-we-contain-claude). The post walks through the containment architectures of Claude.ai, Claude Code, and Claude Cowork; notable findings for harness authors:

- **Three distinct isolation patterns** — Claude.ai uses a server-side ephemeral gVisor container; Claude Code uses a **human-in-the-loop OS sandbox that allows reads, confines writes to the workspace, and denies network by default**; Claude Cowork uses a sealed local VM with workspace + `.claude` mounted and credentials kept in the host keychain.
- **Three vulnerabilities targeted code that executes before the user has consented to anything** — including when a developer clones a repository containing a `.claude/settings.json` which defines a hook.
- **Telemetry showed users approved roughly 93% of permission prompts**, and "the more approvals a user sees, the less attention they pay to each." Approval fatigue is a documented failure mode.
- Core thesis: **rather than supervising what the agent does, supervise what it's able to do** — enforce access boundaries via sandboxes, VMs, and egress controls. (This is the Anthropic-side framing of the same blast-radius posture that motivated this harness's worktree + denylist + sandcastle architecture.)

## 3. Add a `## Gotchas` section convention to `skills/skill-creator/SKILL.md`'s anatomy guidance

**Source:** [Lessons from building Claude Code: How we use skills — Claude Blog, ~May 2026](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills). Key takeaways for harness authors:

```markdown

Per Anthropic's [Lessons from building Claude Code: How we use skills](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills), "the highest-signal content in any skill is the Gotchas section." **Shape:** an `## Gotchas` heading near the end of the SKILL.md body, with short bullets. Example:

\`\`\`markdown
## Gotchas

- The eval workspace is named `<skill>-workspace/`, **not** `<skill>/workspace/` — Claude will sometimes guess the wrong shape and create a nested directory.
- `evals/evals.json` does NOT include assertions in step 1 — they get added in the next step. If you write assertions up-front, the runner ignores them silently.
- The "without_skill" baseline does NOT load *any* skill, including the one being improved. To benchmark against the prior version, snapshot the skill and point the baseline at the snapshot.
\`\`\`

The bullets are *not* exhaustive documentation — they're rescue tape for the parts of the workflow Claude has actually slipped on. Add one when a failure surfaces; never write speculative Gotchas.
```
