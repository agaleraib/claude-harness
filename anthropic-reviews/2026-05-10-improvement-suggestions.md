## 1. Position Anthropic's hosted Code Review + `/ultrareview` alongside the harness's local `code-reviewer` agent

**Source:** [Code Review for Claude Code — claude.com/blog, 2026-05-06](https://claude.com/blog/code-review) (Code w/ Claude conference launch). Pairs with the **`/ultrareview`** slash command surfaced in this session's CLAUDE-Code system guidance — both are the user-/PR-triggered, cloud-fan-out, multi-agent reviewer Anthropic now ships. Background: the [official `code-review` plugin](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/code-review) runs five parallel Sonnet agents at an 80-confidence threshold.

### Why it's relevant
The harness's flagship adversarial agent is `code-reviewer` ([`.claude/agents/code-reviewer.md`](../.claude/agents/code-reviewer.md), prose hits in `README.md:90, 379–394, 1042, 1060`): **local, single-process, rubric-anchored** (it scores against `criteria/`), runs as part of `/commit` *before* anything is pushed. As of 2026-05-06 Anthropic now ships:

- **Code Review** — multi-agent cloud reviewer that fires automatically on every PR for Team/Enterprise plans, dispatches parallel agents per issue class, runs a verification step to filter false positives, and lands an overview comment + inline comments on the PR. Token-billed (~$15–25/PR).
- **`/ultrareview`** — the slash-command, single-shot version: 10–20 min cloud run on the current branch (or a numbered PR), independent reproduction of every finding in a sandbox before reporting. Pro/Max-billed at ~$5–20/run.

These are **complementary, not redundant**. The harness's `code-reviewer`:
- runs *before* push (catches issues at `/commit`);
- consumes < $0.10 per invocation (same Claude Code session);
- scores against project-specific `criteria/*.md` rubrics — Anthropic's reviewer doesn't see those;
- has a documented "blocks merge / degrades quality / minor" priority structure that the harness's `/commit` flow already routes around.

Anthropic's offerings:
- run *after* push (catch issues at PR time);
- read PR history + comments (information `code-reviewer` doesn't have);
- run in parallel agents at confidence-threshold filtering (different recall/precision regime than a single adversarial reviewer).

The README needs **one paragraph** that names this complementary structure so the next time a reader asks "do I still need the local reviewer if I have `/ultrareview`?" the answer is on the page. Today there is **zero mention of `/ultrareview` or hosted Code Review** in the repo (`grep -rn "ultrareview\|claude.com/blog/code-review" .` returns nothing).

+#### How this complements Anthropic's cloud reviewers
+The harness's `code-reviewer` runs **locally, pre-push, against project `criteria/`**, and is invoked synchronously by `/commit`. As of [Code w/ Claude 2026](https://claude.com/blog/code-review), Anthropic also ships two cloud reviewers that operate at different layers: **Code Review** (Team/Enterprise; auto-runs on every PR; fan-out parallel agents + verification step; ~$15–25 per PR) and **`/ultrareview`** (Pro/Max; user-triggered; 10–20 min cloud run on the current branch or a PR; ~$5–20 per run). Use the local `code-reviewer` for the build/review loop before commit (cheap, rubric-anchored, blocks at `/commit`); use Anthropic's cloud reviewers for the post-push pass on substantive PRs that are about to merge (PR-context-aware, multi-agent fan-out). ## 2. Migrate the Anthropic-reviews routine itself to a Claude Code Cloud Routine

**Source:** [Introducing routines in Claude Code — claude.com/blog, 2026-05-06](https://claude.com/blog/introducing-routines-in-claude-code) (Code w/ Claude). Anthropic shipped saved cloud-hosted prompts with **schedule / API / GitHub-event triggers** that run on Anthropic infra without the user's machine being on. Key advantages per the post: laptop can be off; multiple triggers per routine combinable on one definition; cron + GitHub-events + manual all coexist.

### Why it's relevant
The harness already operates an **Anthropic-reviews routine** (this very file is its output): a scheduled prompt that surveys Anthropic's news/engineering posts since the last tracker entry, classifies actionable items, and opens a PR. Today it runs **manually** — the maintainer triggers a Claude Code session, the session does the work, and the resulting PR enters the triage flow described in `anthropic-reviews/README.md`. Two pieces of supporting infrastructure already exist:

- **`skills/session-start/SKILL.md` line 43** documents that `git fetch` is intentional "to ensure branches pushed by automated routines (e.g. the Anthropic-reviews scheduler) are visible locally without moving master." So a scheduler is already anticipated in the harness.
- **`skills/session-start/SKILL.md` lines 107, 118** check for `anthropic-reviews/` to drive a session-start "open PRs to triage" surface.

A Claude Code Cloud Routine could:
1. Run weekly (e.g. `0 8 * * 1` Mondays UTC), or on a `repository_dispatch` GitHub trigger;
2. Execute the same prompt the user runs today (`AGENTS.md` + `anthropic-reviews/README.md` + this routine's instructions);
3. Push the resulting branch and open a PR with the `anthropic-review,suggestions` label.

The maintainer would then triage from the existing PR flow — no behavioral change, just removed friction.

### Why this is `defer`, not `apply`

1. **It works today.** The manual trigger is ~30 seconds of overhead; that's not a pain point worth a setup investment now.
2. **Cloud Routines bill against the Pro/Max plan.** Even at the cheapest tier, a weekly routine that does a multi-page web survey is non-zero recurring cost ($5–10/run by analogy with `/ultrareview`'s pricing band). Solo tooling repo with no revenue — defer.
3. **Routines are new (May 2026).** Schedule semantics, retry behavior, and failure surfaces aren't yet documented in operational depth. Wait a quarter for ergonomics to settle.
4. **Setup is non-trivial.** Connecting a routine to the `agaleraib/claude-harness` repo via GitHub triggers requires connector authorization that the harness's MCP scope doesn't currently grant.
5. **Speculative for solo tooling.** Per the routine's own `apply / defer / reject / spec` rubric: "speculative for solo tooling" is a defer indicator, not a reject indicator — flag it for the maintainer rather than killing it.

### Concrete change (deferred)

None this run. When/if the maintainer wants to take this on:

1. Spec the routine prompt — likely a copy of the routine instructions in this very file's preamble, with the discovery sources hardcoded (anthropic.com/news, anthropic.com/engineering, resources.anthropic.com).
2. Decide trigger: weekly cron vs. a `repository_dispatch` event fired by some upstream signal (e.g. an RSS-watcher GitHub Action). Cron is simpler.
3. Authorize GitHub connector for the routine and confirm it can push branches + open PRs against `agaleraib/claude-harness`.
4. Test with a one-off manual trigger before turning on the schedule.
5. Update `anthropic-reviews/README.md` to document the cloud-routine path alongside the manual trigger.

Routine fires every Monday without the maintainer remembering to trigger it; the existing triage PR flow kicks in unchanged.
