## 2. Add `/context` + prompt-cache-aware `/compact` timing to README's Session-Management Practices table, cite "Maximizing the value of your Claude Code sessions" (2026-08-14)

**Source:** [Maximizing the value of your Claude Code sessions — claude.com/blog, 2026-08-14](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions). Key points relevant to the harness's Session-Management doctrine:
- `/context` in a fresh session shows what's loaded (CLAUDE.md, MCP tool definitions) so you can cut out unnecessary weight — new practice, not currently in the README table.
- `/compact` before taking a break, "since the prompt cache expires after an hour and summarizing a conversation is much cheaper while it's still cached" — sharpens the existing `/compact` row with a *when* rationale beyond "context is growing".
- Session-splitting rationale: "One long session costs more than the same work spread over a few short ones, because turn 40 is also re-reading the 39 turns before it" — corroborates the harness's existing `/clear` guidance without changing it.

### Why it's relevant

The README's Session-Management Practices table (`README.md:862–869`) covers `/clear`, `/compact`, "two corrections → `/clear`", `/rename`, subagents, `/btw`. It does **not** cover `/context` (a load-inspection command) or the cache-window-aware `/compact` timing rule.

`grep -n "/context" README.md` returns:
- `README.md:958–960` — the `ctx: 42% used (58% left)` status line (a display, not a command)
- No hits for the `/context` command itself

The `2026-05-01 §1` entry already added a footnote about `/compact` vs `/clear` cache impact. The 2026-08-14 post supplies the *timing* wedge — before you take a break from the keyboard — which is orthogonal.

### Concrete change

Two touches in `README.md`:

**(a) Add one row to the Practices table (`README.md:862–869`)** — insert between the existing `/compact` row and the "Two corrections" row:

```diff
 | **`/compact Focus on [X]`** | When you can't clear but context is growing | Summarizes old context while preserving what matters. |
+| **`/context`** | Once at the start of a fresh session | Shows what's loaded (CLAUDE.md, MCP tool definitions). Cut anything you don't need so subsequent turns don't re-read it. |
+| **`/compact` before a break** | Before stepping away from the keyboard | The prompt cache expires after an hour — compacting while it's still warm is much cheaper than compacting a cold session on the next return. |
 | **Two corrections → `/clear`** | After correcting Claude twice on the same issue | Failed approaches pollute context. Start fresh with a better prompt that includes what you learned. |
```

**(b) Add one reference bullet to `README.md:1109–1118`**:

```diff
 - [Context Window Visualization](https://code.claude.com/docs/en/context-window) — Understanding what consumes your context
+- [Maximizing the value of your Claude Code sessions](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions) — `/context`, `/clear`, `/compact` discipline; session-split rationale (August 2026)
```

### Expected payoff

Two new practices land in the same table a solo maintainer already reads once a quarter, plus a fresh primary source for the cache-window timing rule that today only appears in `2026-05-01 §1`'s applied footnote. Zero methodology shift — the "context is your most precious resource" doctrine is unchanged; the additions are diagnostics and timing.

### Why this isn't a duplicate of `2026-05-01 §1`

The 2026-05-01 addition was about **billing-mode** (`/clear` resets cache; `/compact` preserves it). The 2026-08-14 post adds a **timing** rule (`/compact` before breaks, cache expires after 1h) and the `/context` command itself (load inspection, not compaction). Complementary.

## 4. Claude Code Plugins (public beta 2026-06-21) as an alternative distribution channel for the harness's skills bundle

**Source:** [Customize Claude Code with plugins — claude.com/blog, 2026-06-21](https://claude.com/blog/claude-code-plugins). Plugins bundle slash commands, subagents, MCP servers, and hooks into one `/plugin`-installable unit; toggle on/off; marketplace + verified badge.

### Why it's relevant (potentially)

The harness distributes today via `setup-harness` — a bash-driven flow that symlinks the repo's `skills/` directory into `~/.claude/skills/` (per this repo's own CLAUDE.md, "Symlinked OUT to `~/.claude/skills/` (claude-harness ships skills to the user's global Claude Code config)"). A plugin bundle could replace that step with a one-line `/plugin install claude-harness` for consumer projects that adopt the harness.

Concretely, the harness has 24 skills (`ls skills/ | wc -l`) plus 6 agents in `.claude/agents/`. All 24 skills use the SKILL.md format the plugin loader expects. A single plugin manifest at the repo root would bundle:
- 24 skills → `commands`
- 6 agents → `agents`
- The two MCP servers referenced today (Playwright, GitHub) → `mcp_servers`
- The catastrophic-command denylist hook and post-commit hook → `hooks`

### Why this is `defer`, not `apply`

1. **Solo maintainer, no team-share problem.** The plugin's core value is packaging + marketplace distribution. Solo tooling doesn't need packaging — the current `setup-harness` symlink workflow works and is scriptable.
2. **Symlinks vs. plugin loader.** Symlinks let the maintainer iterate on `skills/<x>/SKILL.md` and see the change instantly in every project. A plugin adds an install/uninstall + version step that slows the edit-test loop on the harness itself.
3. **Marketplace listing has costs.** Anthropic-Verified badge requires an additional review pass; unverified plugins are still listed but the discovery story is weaker; and marketplace-listed content becomes public-facing (currently the harness is a git repo, not a listed product).
4. **Consumer-project uptake is not the current pain point.** Per `.harness-profile:14` (`audience.size_estimate: "1"`), no external consumer projects install this harness today. The distribution primitive doesn't need to change until at least one does.
5. **Speculative for solo tooling.** Per the routine's own rubric: "speculative for solo tooling" is a `defer`, not a `reject` — flag for the maintainer's awareness, don't kill.

### Concrete change (deferred)

None this run. When/if the maintainer wants to take this on:

1. Add a `.claude-plugin/plugin.json` (or whatever the current schema requires — check the Aug 30 Claude Code Docs) at the repo root that manifests the 24 skills, 6 agents, MCP servers, and hooks.
2. Test-install locally via `/plugin install file://<repo path>` before publishing.
3. Decide whether to publish to Anthropic's plugin marketplace (public) or keep as a private plugin distribution (currently the harness lives on `github.com/agaleraib/claude-harness` and is cloned manually).
4. Cross-reference `setup-harness` — the plugin path may want to *supplement* (not replace) the current symlink flow, so a maintainer working on the harness itself still gets the fast edit-test loop.
5. Update the `INSTALL-FOR-COLLEAGUE.md` file to document the plugin install path.

### Expected payoff (when applied)

External consumers get a one-line install (`/plugin install claude-harness`) instead of a `git clone + setup-harness` flow. Skills toggle on/off individually. Version pinning per-project. None of this matters at `audience.size_estimate: "1"`.

### Verify before applying
1. `find . -maxdepth 2 -name ".claude-plugin" -o -name "plugin.json"` — must return nothing today; if it returns hits, the plugin manifest already exists.
2. `grep -rn "/plugin install\|claude-plugin\|marketplace.json" INSTALL-FOR-COLLEAGUE.md setup-harness/SKILL.md` — must return nothing (would signal plugin path is already documented).
3. Confirm the Claude Code Plugins schema is still in beta (not GA with breaking changes) on the apply date — a schema move between beta and GA is a well-known migration cost, and building against a moving target burns effort.
4. Confirm `.harness-profile:audience.size_estimate` is still `"1"` — if the audience has grown past solo, the defer rationale weakens.

**Recommended verdict:** defer until team grows past solo — no external consumer to serve yet; symlink flow works; plugin adds edit-test friction on the harness itself.
**Status:** PENDING — awaiting triage in PR review
