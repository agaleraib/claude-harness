## 4. Evaluate `@anthropic-ai/sandbox-runtime` as a lighter alternative to sandcastle for `/run-loop`'s container lane

**Source:** [How we contain Claude across products — anthropic.com/engineering, 2026-06-04](https://www.anthropic.com/engineering/how-we-contain-claude). Anthropic published a three-layer containment architecture (environmental isolation + model-level defenses + content access controls) and open-sourced the **Sandbox Runtime (SRT)** as `npm:@anthropic-ai/sandbox-runtime` — built on Linux **bubblewrap** and macOS **seatbelt** at the OS layer, *without* container overhead. Additional context: a February 2026 red-team exercise showed Claude Code phishable into exfiltrating `~/.aws/credentials` 24/25 times; the post frames the sandbox architecture as the mitigation.

### Why it's relevant

The harness has an existing container-based runner (**sandcastle**, `@ai-hero/sandcastle` v0.9.0, per `sandcastle_mattpocock_architecture.md`) — the OS is the security boundary. `/run-loop`'s worktree runner is the non-containered fallback that carries the catastrophic-command-denylist hook + `RUN_LOOP_ENFORCE=1` operator gate. Anthropic's SRT would sit *between* these: **OS-enforced restriction (bubblewrap/seatbelt) without container overhead**.

Concretely, SRT could replace or augment the worktree lane's guardrails (denylist hook + operator gate + egress policy) with OS-level filesystem + network restrictions, potentially removing the need for the operator-installed global PreToolUse hook. Or SRT could sit *inside* the sandcastle container as a defense-in-depth layer.

But **this is speculative for the harness today** — sandcastle is embedded infrastructure (150+ lines of `skills/_shared/loop/` reference it), the worktree lane is operator-gated and working, and the harness has zero SRT experience.

### Concrete change (deferred)

None this run. When/if the maintainer wants to take this on:

1. Read Anthropic's engineering post + the `@anthropic-ai/sandbox-runtime` README end-to-end.
2. Spec a small experiment: use SRT to run **one** `/run-loop` item in a bubblewrap sandbox (linux only), measuring: (a) setup latency vs. sandcastle container spin-up, (b) filesystem + network isolation coverage vs. sandcastle's, (c) interaction with the existing denylist hook.
3. Decide: no-op (SRT redundant with sandcastle), augment (SRT inside sandcastle), or replace-worktree-lane (SRT becomes the "lightweight sandbox" tier between sandcastle and worktree).

### Why `defer`, not `apply` or `spec`

- **Sandcastle works.** No current pain trigger. `defer` beats `spec` when there's no forcing function.
- **Cross-platform.** Bubblewrap is Linux-only; seatbelt is macOS-only. The harness targets both — a hybrid strategy would need per-OS branching.
- **New surface area.** SRT is a fresh open-source package (June 2026 launch); wait a quarter or two for the API to stabilize.
- **Marginal safety gain.** The worktree lane's operator gate + denylist hook already covers the common cases. SRT would elegant-ify this but wouldn't unlock new capability.

### Expected payoff (when applied)

- A middle tier between sandcastle (heavy, cross-repo boundary) and worktree (light, OS-boundary-less) — could let `/run-loop` promote riskier items into SRT + skip the operator gate.
- Alignment with Anthropic's own containment reference architecture — future-proofing against Claude Code shipping SRT-integration primitives.
- Removes the fragility of the operator-installed global PreToolUse hook (currently a "human-only TODO" in `run-loop/SKILL.md`).

**Verify before applying:**

1. `grep -rn "sandbox-runtime\|@anthropic-ai/sandbox\|bubblewrap\|seatbelt" /home/user/claude-harness` — should still return **zero** hits (verified 2026-08-14). If any land, someone started integrating SRT and this § is superseded.

### Why it's relevant (and why the recommendation is `reject`)

The harness already models multi-agent parallel dispatch in three layered ways:

1. **`.claude/agents/orchestrator.md`** — the orchestrator agent picks model + effort per task (routing table at lines 149–151), fans out sub-agents, and closes the loop through `/commit` + `code-reviewer`.
2. **`/run-wave`** — dispatches a whole wave's tasks through the orchestrator, phased dispatch.
3. **`/run-loop`** — the third execution lane; drains ready waves OR ready-for-agent gh issues end-to-end.

Anthropic's `Workflow` tool operates at a *different layer* — inside a single Claude Code session, no PR gate, no cross-session state, no `.harness-state/` journal. It is the *right primitive* for a bounded fan-out within one turn (e.g. reviewing 12 files in parallel adversarially and returning a synthesis); it is the *wrong primitive* for the harness's multi-session, PR-gated, resumable pipeline.
