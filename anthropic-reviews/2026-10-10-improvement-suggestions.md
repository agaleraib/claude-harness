The migration isn't a mechanical find-and-replace. Three design questions surface:

1. **Effort default recalibration.** The Opus 5.5 migration guide (section *Migrating from Claude Opus 4.7*, item 1) states verbatim: *"The token allocation behind each effort level changes on Claude Opus 5.5 compared to Claude Opus 4.7. If Opus 5.5's own API default is `medium`, is `xhigh` still the right stakes-medium default? This is a real decision, not a slug swap.
2. **Thinking is always on with Opus 5.5.** Same migration guide, section *What every request to Claude Opus 5.5 must satisfy*: *"`thinking: {\"type\": \"disabled\"}` and manual thinking budgets ... are rejected."* Nothing in the harness disables thinking today, but any downstream project installing from `setup-harness` that happened to pass `thinking: {"type": "disabled"}` through a wrapper will 400 against Opus 5.5. Worth flagging in the migration note even if the harness itself has no API client code.
3. **Haiku now has effort levels.** Haiku 5.5 is the first Haiku-class model with Low/Med/High/Xhigh/Max — previously the orchestrator's routing table treated Haiku as effort-less (only `low` appears in rows 144–145). The 5.5 refactor can now put Haiku on the same effort axis as Sonnet and Opus, which could change the "Route to Haiku when" bullet list on orchestrator.md:118–121 (today it's capped at scanning / boilerplate; with effort levels it could absorb some bounded-complexity work currently going to Sonnet, at ~1/20 the cost per 1M output tokens: $0.50 vs $10). This is a real design opportunity, not just a slug swap.

Also, Anthropic ships automation for the API-side move: `/claude-api migrate this project to claude-opus-5-5` is bundled in the user-level `claude-api` skill (already visible in this session's available-skills list, triggered on anything mentioning Claude/Anthropic/model IDs). ## 2. Add `docs/procedures/cloud-sessions.md` — one-page cheat sheet for running the harness in Claude Code cloud sessions

**Source:** [Use Claude Code in the cloud — code.claude.com/docs/en/claude-code-on-the-web](https://code.claude.com/docs/en/claude-code-on-the-web) (the field guide referenced in [claude.com/blog Oct 6, 2026](https://claude.com/blog) as "Claude Code in the cloud: a field guide to cloud sessions").

### Why it's relevant

This routine runs **inside a Claude Code cloud session** — the system prompt's "Your current remote execution environment" block is the giveaway. The harness is clearly being used from cloud sessions in production, but the repo has **zero** written guidance for the maintainer or for downstream `setup-harness` consumers on what the cloud session does differently from a local session:

- `grep -rn "cloud session\|--cloud\|--teleport\|cloud environment" /home/user/claude-harness` returns **one hit** — a line inside the 2026-05-10 §1 README edit about the hosted *Code Review* reviewer. Nothing on cloud-session semantics themselves.
- `skills/session-start/SKILL.md` line 43 is already written in anticipation of "automated routines (e.g. the Anthropic-reviews scheduler)" running the harness non-interactively — but there's no doc that says "when you're running in a cloud session, X file layout holds and Y env vars matter."

A one-page cheat sheet would document the concrete differences a cloud session imposes on the harness's own conventions:

1. **The VM clones your remote branch, not your local checkout.** From the docs: *"The cloud VM clones your current directory's GitHub remote at your current branch, not your local checkout, so push first if you have local commits."* This matters for the harness's `.harness-state/` writes — anything in `.harness-state/` that isn't committed before `claude --cloud …` is run never reaches the cloud VM. Worth calling out alongside `skills/session-end/SKILL.md`'s existing "write `last_exit.md` and commit" ritual.
2. **Local bundle upload is a fallback.** From the docs: *"When you run `claude --cloud` from a repository that has no git remote, or from a github.com repository that the Claude GitHub App isn't installed on, Claude Code bundles your local repository and uploads it directly to the cloud session."* Also: *"To upload a bundle even when Claude Code would otherwise clone from the remote, set `CCR_FORCE_BUNDLE=1`."* A `.env` or `*.pem` in uncommitted state is left out of the bundle on macOS/Linux/WSL — but **native Windows uploads them as-is**. The harness's secret-scan git hook (recently landed per `e0328b8`) backstops this on Windows.
3. **Scratchpad / env-var env.** Cloud sessions set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` themselves, overriding any value a user puts in environment variables, so manual tuning there is a no-op. To change the auto-compact window, set `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in the environment config instead.
4. **Agent Teams gate.** Cloud sessions keep [Agent Teams](https://code.claude.com/docs/en/agent-teams) off by default; `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` enables them. The harness's orchestrator agent already does parallel dispatch; if the maintainer wants orchestrator subagents to run as a formal Agent Team on cloud, this is the switch.
5. **Teleport semantics.** `claude --teleport <session-id>` pulls the cloud session's branch back into a local checkout. Teleport requires a clean working tree in the local checkout — this is important given the harness's `.harness-state/` writes, which are often uncommitted on a day-to-day basis.
6. **`subscribe_pr_activity` for created PRs.** The harness's `CLAUDE.md` already carries the GitHub Integration block (lines 1–50-ish of the Session-specific guidance / GitHub Integration section) that subscribes to PR activity after a `create_pull_request`. In a cloud session, this is especially useful because the laptop can be off — a cross-reference from the new procedure doc to the existing `CLAUDE.md` section would make the pattern discoverable.
7. **Routines productized.** The deferred 2026-05-10 §2 (Cloud Routines) is now at [docs/en/routines](https://code.claude.com/docs/en/routines) with full operational docs — scheduled trigger / API trigger / GitHub-event trigger, each run as a cloud session. This procedure doc is a good place to drop one cross-reference bullet pointing at that deferral, so a future reader sees the two together.

```markdown
# Cloud sessions — running the harness in `claude --cloud`

**Source:** https://code.claude.com/docs/en/claude-code-on-the-web (field guide, Oct 2026)

## When the harness runs in a cloud session
Every scheduled Anthropic-reviews run; any `claude --cloud "..."` from a terminal; any Routine (see `docs/en/routines`); any PR triggered via `/autofix-pr`.

## Repo state the VM sees
- Cloned at your current branch's **remote HEAD** — local-only commits are invisible until pushed.
- Falls back to a local bundle upload if there's no remote or the Claude GitHub App isn't installed on the repo. On native Windows the bundle includes uncommitted secrets as-is; the global secret-scan pre-commit hook (introduced in `e0328b8`) is the backstop.
- Override to force-bundle: `CCR_FORCE_BUNDLE=1`.

## `.harness-state/` and other write targets
- The cloud VM has a session-scoped scratchpad (`/tmp/claude-0/-home-...-claude-harness/<session-id>/scratchpad`) for throwaway files. Use it, not `/tmp`.
- Anything written to `.harness-state/` must be committed and pushed before the next cloud session can read it — the VM is reclaimed on inactivity and the next run clones fresh.

## Env vars the harness interacts with
- `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` — turn on Agent Teams for orchestrator subagents (off by default).
- `CLAUDE_CODE_AUTO_COMPACT_WINDOW` — change the auto-compact window (cloud sessions set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` themselves, overriding any value you set there).
- `CCR_FORCE_BUNDLE=1` — bundle local repo state even when clone would succeed.

## Teleport back to local
`claude --teleport <session-id>` requires a clean local working tree. The harness's `.harness-state/` writes are usually uncommitted, so stash them (`git stash -u`) before teleport. See `docs/en/claude-code-on-the-web#from-cloud-to-terminal`.

## See also
- `.github/CLAUDE.md` — GitHub integration, PR activity subscription, created-PR follow-through.
- 2026-05-10 §2 (DEFERRED) — migrating the Anthropic-reviews routine itself to a Cloud Routine, now that `docs/en/routines` is published.
```
