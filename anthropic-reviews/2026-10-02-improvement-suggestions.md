## 3. Add a cache-protection callout to `README.md § Session Management` + a bullet in `AGENTS.md`

**Source:** [Coding sessions are longer and use more context. Claude Opus 5.5 is built with that in mind. — claude.com/blog, 2026-09-24](https://claude.com/blog/claude-opus-5-5-built-for-coding-sessions-that-use-more-context)

### Why it's relevant

The Opus 5.5 coding-sessions post names three explicit cache-protection practices:

1. **Pick model at session start, not mid-session** — model switches invalidate the cache prefix.
2. **Compact before stepping away, not after** — compact-then-wait preserves the cached prefix for the next turn.
3. **Use the one-hour cache lifetime** (available on API keys and Bedrock/Vertex) — reduces cache churn in long sessions.

The harness's `README.md § Session Management` (lines 860–873) already has `/clear` and `/compact Focus on [X]` guidance, framed around context freshness, not cache efficiency. The two framings don't conflict — cache efficiency is a separate axis — but neither of these three practices is mentioned anywhere in the repo (`grep -rn "cache miss\|cache lifetime\|cache prefix\|model.switch\|switch.model" .` returns nothing in `README.md`/`AGENTS.md`/`skills/`).

Not a bug today: the harness doesn't instruct mid-session model switching, and `/compact` is already recommended before context fills. But (a) `/micro` sometimes nudges toward a model switch; (b) `last_exit.md` ritual sometimes compacts *after* stepping away; (c) the one-hour cache lifetime is not surfaced anywhere.

### Concrete changes

Add one block to `README.md § Session Management > Practices` (after the `/compact` row, around line 866):

```markdown
### Cache-efficient session hygiene

Opus 5.5's cache reads cost ~1/5 of a fresh token — so cache invalidation is now a measurable cost, not just a nicety. Three habits from Anthropic's [2026-09-24 coding-sessions post](https://claude.com/blog/claude-opus-5-5-built-for-coding-sessions-that-use-more-context):

| Habit | Why |
|---|---|
| **Pick your model at session start, not mid-session** | Switching model (e.g. opus → sonnet via `/model`) invalidates the cached prefix on every subsequent turn. If you want to downshift, start a new session. |
| **Compact *before* stepping away, not after** | A compact-then-idle pattern keeps the cached prefix warm for your next turn. Compact-after-return pays the full re-encoding cost. |
| **Enable the 1-hour cache lifetime** (API-key / Bedrock / Vertex) | Default cache TTL is 5min. The 1-hour variant costs more per cache *write* but is amortized across turns in a long session — net cheaper for `/run-wave`-style multi-hour runs. |
```

Mirror as one bullet in `AGENTS.md § Loop protocol` (next to the existing `/clear`/`/compact` guidance): *"When operating on Opus 5.5, prefer picking the model at session start, compact-before-stepping-away, and enable the 1-hour cache TTL where supported — see README §Session Management > Cache-efficient session hygiene."*

### Expected payoff

Session-cost footprint drops on long runs (`/run-wave`, `/run-loop`, planning-loop). No behavioral change — just hygiene that the maintainer can now point to when a session feels expensive.

**Verify before applying:** `grep -rn "cache lifetime\|cache prefix\|cache miss\|1-hour cache\|model switch" README.md AGENTS.md skills/ 2>/dev/null` still returns nothing when read tomorrow; the 2026-09-24 blog post URL still resolves.

**Recommended verdict:** defer until pain — Interesting, measurable, but no concrete symptom today. Lift the recommendation the first time a `/run-wave` session logs 10+ unexpected cache-miss re-encodings, or when the maintainer notices a `/compact` after `last_exit.md`.

## 4. Note Claude Code **mods** as a parallel plugin surface in README + `setup-harness`

**Source:** [Customize Claude Code with mods — claude.com/blog, 2026-10-01](https://claude.com/blog/claude-code-mods) · [Mods overview — code.claude.com/docs/en/plugins/mods/overview](https://code.claude.com/docs/en/plugins/mods/overview)

### Why it's relevant

Mods are a new (Oct 1, 2026) Claude Code plugin surface: TypeScript functions that run **inside Claude Code's process**, hooking events like `tool.call`, `ui.render`, `prompt.submit`. They can draw UI (panes, bands above the prompt), replace Claude Code's own interface elements, intercept tool calls, and share state between hooks. The sample mods in `claude-code-playground` are illustrative:

- `token-weather` — context-window forecast drawn above the prompt
- `blast-radius` — holds `rm -rf`/force-push, shows what would change, asks to proceed
- `replay-theater` — `/replay` command that steps through the file edits of the last turn

This harness ships **skills** via symlink to `~/.claude/skills/` (per `CLAUDE.md § Skills directory layout`). Skills, mods, settings-hooks, and MCP servers are four non-overlapping surfaces per the mods-overview comparison table — the harness uses skills + settings-hooks today (the latter via `~/.claude/settings.json`'s denylist and `PreToolUse` scanner for `/run-loop`'s catastrophic-command safety). No mods.

A mod is **not** a required addition today — nothing in the harness's roadmap needs an in-Claude-Code UI pane, tool-call interception, or `ui.render` rewriting (`skills/_shared/loop/safety/denylist.ts` is a `PreToolUse` *settings-hook*, which is cheaper to install and audit than a mod). But:

- The next time a reader asks "could the harness ship a mod?" (plausible — `blast-radius` would complement the denylist by making it visible in-session), the comparison table is one click away.
- `grep -rn "\\bmod\\b\\|/plugin\\b\\|plugin\\.json\\|~/.claude/plugins" README.md CLAUDE.md AGENTS.md skills/setup-harness/SKILL.md` returns **zero** mentions of this surface. The repo currently reads as if skills + settings-hooks are the only two options.

+└── plugins/                        # (optional) Claude Code mods — TypeScript function hooks that run inside Claude Code's process. Different surface from skills; see https://code.claude.com/docs/en/plugins/mods/overview for the comparison table. The harness ships no mods today.

#### Mods vs. settings-hooks vs. skills

Claude Code v2.1.287+ ships three customization surfaces that overlap:

- **Settings hooks** — shell commands in `~/.claude/settings.json` fired on lifecycle events (`PreToolUse`, `PostToolUse`, `SessionStart`, …). The harness uses these (`skills/_shared/loop/safety/denylist.ts` + the operator-installed `PreToolUse` matcher).
