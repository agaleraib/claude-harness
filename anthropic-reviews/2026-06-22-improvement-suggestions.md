## 2. Adopt a `## Gotchas` section convention via `skills/skill-creator/SKILL.md` + seed one or two existing skills

**Source:** [Lessons from building Claude Code: How we use skills — claude.com/blog, 2026-06-03](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills) (Thariq Shihipar). Anthropic's headline craft note: "The highest-signal content in any skill is the Gotchas section. … Every time Claude fails while using a skill, the owner should add that failure to the gotchas, and over time, the skill becomes robust not because someone predicted everything, but because they captured every mistake."

### Why it's relevant
This repo distributes 24 SKILL.md files under `skills/`. `grep -rln "## Gotchas\|## Pitfalls\|Gotchas" skills/` returns **zero hits** in skill bodies today (the only `Gotcha` hits in `skills/` are inside `setup-harness/SKILL.md` as a vendored Anthropic mention, not the convention itself). The harness already vendors Anthropic's skill-creator (`skills/skill-creator/`, Apache-2.0 fork) — that's the natural insertion point for the convention to propagate to every future skill.

The harness's own loop protocol explicitly captures the same idea informally: `AGENTS.md` "What to avoid" is a Gotchas section for the protocol itself. Pulling the pattern down to the per-skill level is consistent with where the project has already landed.

Two complementary edits:
- **Convention edit:** add a "Gotchas" section to skill-creator's template / authoring guidance so new skills include it by default.
- **Seed edit:** pick the two highest-traffic skills (`run-loop` and `commit` are the two end-of-day-critical ones) and append a `## Gotchas` section with one or two real failure modes the maintainer has hit. Per Anthropic: *"Most of the best skills began as a few lines and a single gotcha, then got better because people kept adding to them as Claude hit new edge cases."*

### Concrete change

**A. Update `skills/skill-creator/SKILL.md`** — append a short authoring note (e.g. after the existing "Cool? Cool." line at `SKILL.md:30`):

```diff
+## A required section for every skill: Gotchas

Build one up incrementally — every time Claude fails while using your skill, add the failure (and the fix) as one bullet. +Template (append near the bottom of every new `SKILL.md`):

+```markdown

## 3. Position Anthropic's `/loop` + `/goal` (dynamic workflows) alongside the harness's `/run-loop` skill in WORKFLOW.md

**Source:** [A harness for every task: dynamic workflows in Claude Code — claude.com/blog, 2026-06-02](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code). Anthropic ships two interactive slash commands as part of the dynamic-workflows release: `/loop` (run a prompt or slash command on a recurring interval) and `/goal` (set a hard completion requirement for an agentic task). The post frames them as ways to fight "agentic laziness", "self-preferential bias", and "goal drift" in long-horizon tasks.

### Why it's relevant
The harness already has a **`/run-loop`** skill (`skills/run-loop/SKILL.md`) that drives a stream of work items (board waves or tracker issues) end-to-end behind a mechanical gate (per `AGENTS.md` "Loop protocol"). The name overlap with Anthropic's brand-new `/loop` is going to confuse future readers — exactly the same pattern as 2026-05-10 §1 (Code Review / `/ultrareview` vs the harness's `code-reviewer`), which was applied successfully.

These are **complementary, not redundant**:

- Anthropic's `/loop` — interactive, in-session, "re-run this prompt every N minutes". Token-billed against the user's Claude Code plan. No mechanical gate, no merge semantics, no work source.
- The harness's `/run-loop` — non-interactive driver that walks a queue of `### Wave N` blocks (or tracker issues), runs each through a per-item gate (verify → review → atomic merge), stops on cap/stall/drain. Defined by spec; receipts under `.harness-state/`.
- Anthropic's `/goal` — interactive, in-session, "don't declare done until this rubric is satisfied". Counters the model's tendency to short-circuit on complex tasks.
- The harness's per-wave exit gate (per spec) is the durable analog of `/goal`, but for queued / unattended work.

The slash-command list in this session's `available-skills` shows `/loop` is already auto-loaded by Claude Code (an Anthropic-managed user-level skill), so it's reachable from any harness session — not a hypothetical.

### Concrete change

```markdown
> **Not the same as Anthropic's `/loop` and `/goal`.** Anthropic's [`/loop`](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code) (re-run a prompt on a recurring interval) and `/goal` (block "done" until a rubric is satisfied) are *interactive*, *in-session* slash commands that ship with Claude Code. The harness's `/run-loop` is a *non-interactive driver* that walks a queue of board waves (or tracker issues), runs each through a mechanical exit-gate + review + atomic-merge sequence, and stops on cap/stall/drain. The two are complementary: use Anthropic's `/loop` for human-in-the-loop recurring prompts during an active session; use the harness's `/run-loop` for unattended, gated drain of the work queue.
