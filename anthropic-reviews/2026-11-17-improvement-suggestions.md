## 1. Refresh `.harness-profile` model pin from Opus 4.7 / Sonnet 4.6 to Opus 5.5 / Sonnet 5.5

**Source:** [Introducing Claude Opus 5.5 — anthropic.com, 2026-09-22](https://www.anthropic.com/claude-opus-5-5), [Introducing Claude Sonnet 5.5 — 2026-09-28](https://www.anthropic.com/claude-sonnet-5-5), [Introducing Claude Haiku 5.5 — 2026-10-07](https://www.anthropic.com/claude-haiku-5-5), [Introducing Claude Fable 5.2 and Claude Mythos 5.2 — 2026-11-09](https://www.anthropic.com/claude-fable-and-mythos-5-2).

### Why it's relevant

`.harness-profile` pins the orchestrator's primary/fallback models and is the single source of truth every skill reads at dispatch time. The current pin:

```yaml

  primary: claude-opus-4-7
  fallback: claude-sonnet-4-6
  effort_default: xhigh

…was set on 2026-04-11 by the `.harness-profile` generation (spec `docs/specs/2026-04-19-harness-model-pin-and-effort-routing.md`, wave 1). Since then Anthropic has shipped four model families, two of them explicitly positioned as the daily driver this profile needs to track:

## 2. Cross-reference the components-of-agent-memory research post as prior art in the 2026-05-13 memory-redesign spec and in `AGENTS.md` memory section

**Source:** [The components of agent memory — anthropic.com/research, 2026-11-06](https://www.anthropic.com/research/components-of-agent-memory).

### Why it's relevant

The post lays out five components of agent memory (transcripts, memory notes, memory representations/wikis, injected context, dreaming) with empirical evidence for each. Two of its concrete claims **directly match choices already made** in the harness's 2026-05-13 memory-system-redesign spec:

1. **Per-entity pages > shared tables.** The post's benchmark: a shared table lost data when agents overwrote each other, while per-contract pages raised graded facts from 41/57 to 57/57. The harness already made this call — `~/.claude/memory/FEEDBACK.md` is an **index** of pointers, and the actual detail lives in `~/.claude/memory/feedback/<slug>.md` per-pattern files. The redesign spec (`docs/specs/2026-05-13-memory-system-redesign.md` Data Model section, "Entity: shared user-global root") codifies this exactly.

2. **Injected context must stay small.** The post quotes: *"[Claude Code's auto memory] loads only the first 200 lines or 25 KB of `MEMORY.md`"* and *"our documentation on Claude Code warns that longer instruction files reduce adherence."* The harness already has hard caps on every shared-root file (USER.md ≤1KB, FEEDBACK.md ≤5KB, REFERENCES.md ≤2KB, PROJECTS.md ≤4KB) per the redesign spec's Data Model section.

One component is **not** implemented: **dreaming** (offline consolidation — reviewing transcripts + notes to correct wrong notes, refine wikis, promote durable notes into injected context). The harness has `/memory-prune` (dry-run cap enforcement) and the session-end skill (`skills/session-end/SKILL.md`), but no offline-consolidation pass that runs between sessions to update `feedback/<slug>.md` files or rewrite `FEEDBACK.md` pointers from aggregate evidence.

The post's quantitative claim about dreaming: *"wiki-only score rose from 13% to 48% over 128 sessions"* — i.e. dreaming's value shows up at scale, not in single sessions. The solo-maintained harness does not have 128-session volume per `feedback/<slug>.md` topic, so the ROI case for building a dreaming pass is thin today. But the parking-lot note is worth having.

### Concrete change

**Two small edits, both bookkeeping-level:**

**A. Append one sentence + link to the Prior Work section of the 2026-05-13 redesign spec** — currently at `docs/specs/2026-05-13-memory-system-redesign.md` line ~95. Insert a new bullet under "Builds on:":

 - [Universal Harness Protocol v2](2026-04-30-universal-harness-protocol-v2.md) — receipt schema, plan.md shape, four-section index
+- Corroborated by [Anthropic's Nov 2026 research on agent memory components](https://www.anthropic.com/research/components-of-agent-memory): the per-entity `feedback/<slug>.md` layout matches the post's "per-contract pages > shared table" finding (41/57 → 57/57 graded facts); the hard caps on `USER.md` / `FEEDBACK.md` / `REFERENCES.md` / `PROJECTS.md` match Claude Code's own auto-memory limit of "first 200 lines or 25 KB of MEMORY.md" that the post cites.
```

**B. Append one bullet to `AGENTS.md` ## Memory section** (currently around line 60 — the five-entity summary) citing the post as the external evidence base for the choices already made. One line, not a paragraph.

**C. Add one parking-lot item** for **dreaming** (offline consolidation). This is **not** a design doc; it's a flag for future-you so the gap is written down somewhere durable:

```diff
 ## Open side-quests
 ...
+- **Dreaming / offline memory consolidation** (2026-11-17): Anthropic's Nov 2026 research on agent memory notes a "dreaming" pass that reviews transcripts between sessions, corrects wrong memory notes, refines per-entity pages, and promotes durable notes into injected context. Wiki-only scores rose from 13% → 48% over 128 sessions in their benchmark. The harness has `/memory-prune` (cap enforcement, manual-triggered) and `session-end` (closing-ritual), but no scheduled consolidation pass that re-reads `~/.claude/memory/feedback/*.md` to merge duplicates, promote stable patterns, or archive resolved ones. ## 3. Scan persistent harness state for prompt-injection markers before session-start reads it

**Source:** [How we contain Claude across products — anthropic.com/research, 2026-05-25](https://www.anthropic.com/research/how-we-contain-claude), recommendation #14: *"Guard persistent state. Scan memory files, CLAUDE.md files, and session startup inputs for injected instructions, since poisoned state reloads every session."*

### Why it's relevant

The harness has three categories of persistent state that satisfy the post's threat model:

1. **Session memory files** — `~/.claude/memory/*.md` (shared root: `USER.md`, `FEEDBACK.md`, `REFERENCES.md`, `PROJECTS.md`, `feedback/<slug>.md` detail files, `archive/`). The 2026-05-13 memory redesign migrated 20+ per-cwd feedback files into this shared root. Per that spec, FEEDBACK.md is `/memory-prune`-writable + humans-append-ok; `feedback/<slug>.md` is append-ok by auto-memory AND human. **Any auto-memory append is a vector** — if a session reads untrusted content and the model decides a slogan from that content is "a pattern worth remembering", the slogan lands in a `feedback/<slug>.md` file that reloads next session.

2. **In-repo static prompt files** — `CLAUDE.md`, `AGENTS.md`, every `skills/*/SKILL.md`. These go through git review, so the attack surface is narrower (an injection needs to pass PR review or a hook), but they're still read-on-session-start.

3. **Session-start injection** — the `session-start` skill reads `.harness-profile`, `.harness-state/last_exit.md`, `parking_lot.md`, `.harness-state/today_goal.md`, `docs/plan.md`, and `.harness-state/current_phase` unconditionally and prints them as context. `last_exit.md`, `today_goal.md`, and `parking_lot.md` are model-written (session-end, `/park`) with no automated scan.

Current harness scan surface for prompt injection:

```
$ grep -rn "prompt injection\|canary\|scan.*memory\|scan.*CLAUDE" skills/ README.md AGENTS.md
skills/setup-harness/SKILL.md:149: "...Auto Mode keeps the classifier's prompt-injection mitigations active."
# (the rest of the matches are about "credential injection" or "context injection" — unrelated)
```

So the only prompt-injection awareness today is a one-line note recommending Auto Mode for isolated containers — which delegates the problem to Claude Code's auto-mode classifier. That classifier sees **tool calls**, not **persistent files read into context at session-start**. The post's rec #14 is about the latter.

The post recommends two mechanisms: (a) explicit scanning before load, (b) canary strings embedded in sensitive content to detect spread.

### Concrete change

**Minimum-viable version** — add a non-blocking advisory scan to `skills/session-start/SKILL.md` Step 2 (after the parallel reads, before the context header is printed). Zero runtime dependency; uses grep + a seed pattern list.

```diff
 ## Step 2: Read current state
 ...
 ```bash
 git fetch origin --prune --quiet 2>/dev/null
 cat .harness-state/last_exit.md 2>/dev/null
 cat .harness-state/current_phase 2>/dev/null
 cat parking_lot.md 2>/dev/null
 ls docs/specs/*.md 2>/dev/null | tail -3
 stat -f "%Sm" docs/architecture.md 2>/dev/null
 stat -f "%Sm" docs/plan.md 2>/dev/null
 git log --oneline -10
 git status --short
 ```
+
+## Step 2c: Scan persistent state for prompt-injection markers (non-blocking advisory)
+
+Reads `~/.claude/memory/*.md` + the in-repo static prompt files + the session-start input files and greps for known injection shapes. Writes a one-line warning to the context header if any match. Never blocks session open; the operator decides whether to clean the hit.
+
+```bash
+# Known injection shapes (add as incidents surface, keep the list short):
+patterns='ignore (previous|the above|all).*(instructions|directions)\|disregard.*(prior|above|previous)\|you are (now|instead) (a|an|the|acting as)\|new (system|assistant) (prompt|message|instructions)\|system[:\s].*override\|BEGIN (PROMPT|SYSTEM) INJECTION'
+hits=$( \
+  { grep -rEnl "$patterns" ~/.claude/memory/*.md 2>/dev/null \
+  ; grep -rEnl "$patterns" CLAUDE.md AGENTS.md 2>/dev/null \
+  ; grep -rEnl "$patterns" skills/*/SKILL.md 2>/dev/null \
+  ; grep -rEnl "$patterns" .harness-state/last_exit.md parking_lot.md .harness-state/today_goal.md 2>/dev/null \
+  ; } | sort -u \
+)
+if [ -n "$hits" ]; then
+  echo "⚠️ Prompt-injection scan found suspicious markers in:"
+  echo "$hits" | sed 's/^/    /'
+  echo "   Review before continuing — these files auto-load into session context."
+fi
+```
+
+This is an **advisory**, not a block. Pattern-matching will false-positive (the pattern list above hits any doc that *quotes* an injection example — including this `SKILL.md` itself the first time the scan runs on it). Treat the first run as a baseline: the operator either confirms each hit is a quoted-example-not-live-injection and appends an explicit `# prompt-injection-example:` annotation that the scan excludes, or cleans the file. After the baseline, hits should be rare — a new hit means someone or some skill added injection-shaped content that wasn't there before.
```

Also add one line to `AGENTS.md ## What to avoid` (per the Memory section's shape):

```diff
 - Don't bake dynamic content (timestamps, build IDs, absolute paths, per-session counters) into static prompt files ...
+- Don't write **model-produced strings verbatim** into `~/.claude/memory/feedback/<slug>.md` without stripping leading/trailing instruction-shaped text (e.g. "ignore previous instructions", "you are now…", etc.) — auto-memory appends land in session context next open, so a poisoned pattern persists. The session-start scan is an advisory, not a guarantee.
```

### Expected payoff

- **One line of defense** against the cheapest form of attack on a Claude Code harness: a model-authored note or a PR-reviewed CLAUDE.md edit that embeds an instruction-shaped sentence. A grep that fires on session-start costs < 50ms and produces one of two outcomes — a hit (operator eyeballs it) or no hit (session proceeds normally).
- **Low risk** because the scan is advisory, not a block. False positives are visible and annotatable.
- **Explicit threat-model documentation.** The AGENTS.md line makes the risk category explicit; future contributors see "don't paste model output verbatim into persistent files" as a rule.

### Why `defer`, not `apply`

Three reasons:

1. **No incident yet.** The post's recommendation is pre-emptive. The harness is solo-maintained; the attack surface is narrow (only the operator's own auto-memory + PR-reviewed static files). An attack-free year doesn't prove safety, but it does lower the urgency of pre-emption.
2. **False-positive discovery cost.** The first run of the scan will hit **this very suggestion file** plus any prior anthropic-review file that discusses prompt injection in examples. The operator has to triage every hit as "example, not live payload" and either annotate or whitelist. That triage is 15–30 minutes of noise before the scan quiets down — worth doing when there's a concrete reason, not as housekeeping.
3. **Pattern-list maintenance is open-ended.** The post recommends incident-driven pattern updates; without incidents, the list is guesswork.

Promote to `apply` when any of these fire: (a) a `feedback/<slug>.md` with model-generated content lands and later proves to have had injection-shaped text; (b) the harness grows to multi-operator (`.harness-profile team.size: solo` → `team`); (c) Claude Code's auto-memory ever auto-appends from an untrusted MCP tool output without a filter.

**Verify before applying:**
1. `grep -rn "prompt-injection scan\|injection markers\|Step 2c" skills/session-start/SKILL.md AGENTS.md` — must return zero hits today; if any hit, scan is already in place and § is stale.
2. `.harness-profile` — confirm `team.size: solo` still holds. If `team.size: team` or larger, promote the recommended verdict from `defer` to `apply` (shared memory root + multi-operator means auto-memory comes from more sessions than the operator reviews).
3. Confirm the scan patterns don't false-positive on the harness's **own documentation of injection** — before committing, run the proposed pipeline against the current tree and triage each hit. If the hit count exceeds ~10 files, the pattern list is too broad; tighten before shipping.

**Recommended verdict:** defer until first injection incident, or until `team.size` leaves solo — cheap, low-risk pre-emption, but the real incident cost is still zero and the false-positive triage has a real cost. Document now (one parking-lot line) so the gap stays visible; build the scan when triggered.
**Status:** PENDING — awaiting triage in PR review

## 4. Agent-Skills donation to the Agentic AI Foundation — any SKILL.md format changes to adopt?

**Source:** [Donating Agent Skills to the Agentic AI Foundation — anthropic.com/news, 2026-10-22](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation). Standard now lives at agentskills.io, GitHub org, and the AAIF (Linux Foundation project that also hosts MCP).

### Why it's relevant

The harness ships **26 skills under `skills/`**, each with a `SKILL.md` file carrying YAML frontmatter (`name` + `description` + sometimes `argument-hint`). This exactly matches the spec Anthropic donated: *"a skill is a folder containing a SKILL.md file that teaches an agent a task or domain, plus any scripts or reference material it needs."*

If the AAIF-governed spec were to introduce breaking changes to the format — new required frontmatter fields, a different folder shape, a schema on `description` wording — then every skill in `skills/*/SKILL.md` would need a sweep. **This is the question worth answering.**

The announcement itself names no breaking changes. It names:
- The **standard name** (Agent Skills), **logo**, GitHub org, and `agentskills.io` domain all move to AAIF.
- Two individual Lead Maintainers (David Soria Parra, Mahesh Murag).
- Planned roadmap items — versioned releases, formal proposal process, security guidance for skill authors + installers. **None are specified yet.**
- "You can keep using the standard or contribute to it without joining AAIF."

The repo's SKILL.md files are compatible with the current spec. The announcement is governance-level, not schema-level.

### Concrete (non-)change

**No code or docs edit.** Specifically:

- **Skills format.** `skills/*/SKILL.md` already matches the donated spec. `grep -rn "^---$" skills/*/SKILL.md | wc -l` = 17 files with frontmatter today; the remaining ~9 skills use structural-markdown-only (no frontmatter), which the spec allows. No normalization needed.
