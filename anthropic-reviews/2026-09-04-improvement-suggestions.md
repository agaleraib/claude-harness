## 1. Cite "How we contain Claude across products" in AGENTS.md + cross-reference from `sandcastle_mattpocock_architecture.md`

**Source:** [How we contain Claude across products — Anthropic Engineering, 2026-05-28](https://www.anthropic.com/engineering/how-we-contain-claude)

### Why it's relevant

Anthropic's May 28 engineering post walks through the containment architecture used across claude.ai, Claude Code, and Cowork — a **three-tier posture**: VM for the strongest isolation (claude.ai), container for medium (Cowork), worktree + hooks + egress allowlists for the weakest (Claude Code local). It also names the concrete metric behind Auto Mode's design: telemetry showed users approved ~93% of permission prompts, and the more approvals they saw, the less attention each got — driving the classifier-based Auto Mode that the harness already documents in `skills/setup-harness/SKILL.md:141`.

The harness implements exactly this three-tier posture today:
- **Sandcastle** (`sandcastle_mattpocock_architecture.md`) = container-tier isolation
- **Worktree runner** (`.claude/worktrees/agent-<id>/`, per `skills/run-loop/SKILL.md:64`) + **catastrophic-command denylist PreToolUse hook** (`skills/_shared/loop/safety/denylist.ts`) + **`worktree_egress_allowlist`** in `.harness-profile` = worktree-tier
- No VM tier (the harness targets solo Claude Code, not multi-tenant surfaces)

Currently there is **no back-pointer** from either `AGENTS.md` or `sandcastle_mattpocock_architecture.md` to the Anthropic post that ratifies this architecture. A future reader (or future-you) trying to justify the sandcastle-vs-worktree split has to reason it from scratch. A one-paragraph appendix + one cross-reference fixes that.

### Concrete change

**(a)** Add a new appendix section to `AGENTS.md` (after `## Memory`), verbatim:

```markdown
## Containment posture

The harness implements a **two-tier** cut of the three tiers Anthropic
describes in [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)
(2026-05-28):

| Anthropic tier | Anthropic surface | Harness surface |
|---|---|---|
| VM isolation | claude.ai | not applicable (harness targets local Claude Code, not multi-tenant) |
| Container isolation | Cowork | Sandcastle (`sandcastle_mattpocock_architecture.md`) |
| Worktree + hooks + egress allowlist | Claude Code local | `.claude/worktrees/agent-<id>/` + `skills/_shared/loop/safety/denylist.ts` + `worktree_egress_allowlist` in `.harness-profile` |

The `/run-loop` skill enforces the correspondence: worktree items are refused

container is their boundary.
```
