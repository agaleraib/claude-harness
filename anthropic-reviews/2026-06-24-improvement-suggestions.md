## 3. Cite the Workflow / dynamic-workflows primitive in `orchestrator.md` as the in-session complement to the harness's spec-driven orchestrator

**Source:** [A harness for every task: dynamic workflows in Claude Code — claude.com/blog, 2026-06-02](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code). Anthropic shipped a Claude Code primitive that lets Claude write its own ad-hoc harness inside a single session, triggered by the phrase "make a workflow" or by the `ultracode` effort setting. The post enumerates **six composable patterns**: classify-and-act, fan-out-and-synthesize, adversarial verification, generate-and-filter, tournament, and loop-until-done. The post explicitly names two failure modes ("agentic laziness" and "self-preferential bias") that the dynamic workflow is designed to mitigate.

### Why it's relevant

The harness ships a runtime orchestrator at `.claude/agents/orchestrator.md` (384 lines) that:
- Reads a **pre-written spec** at `docs/specs/<date>-<topic>.md`.
- Routes each task to opus / sonnet / haiku at runtime.
- Picks `effort` per task (low / medium / high / xhigh).
- Logs to `.harness-state/orchestrator.{log,jsonl}` per a documented logging contract.
- Runs `/commit` (including the `code-reviewer` agent) between tasks.

Anthropic's Workflow primitive operates at a **different layer**:
- No spec required — Claude writes the JavaScript orchestration script itself in-session.
- Composes the six named patterns (classify, fan-out, adversarial, generate-and-filter, tournament, loop-until-done) without the user having to author them.
- Default behavior: triggered by the user typing "make a workflow" or by `ultracode`.

These are **complementary, not redundant** — the same shape as the `code-reviewer` vs hosted Code Review / `/ultrareview` framing that 2026-05-10 §1 added to the README (and APPLIED). A reader staring at the orchestrator agent's 384 lines today, after seeing "A harness for every task" trending in their Claude Code dashboard, will ask exactly the question the 2026-05-10 § anticipated: *"Is the local orchestrator still needed if Claude Code now writes its own workflow per task?"* The answer is yes — they sit at different layers (spec-driven, persistent log-contract, model routing across a phase vs in-session, ad-hoc, throwaway script) — but the answer should live in `orchestrator.md`, not in the next maintainer's head.
