Anthropic finally published a canonical when-to-use-which-primitive guide covering the seven methods that shape Claude Code behavior: **CLAUDE.md, rules, skills, subagents, hooks, output styles, appended system prompt.** Each is characterized on three axes:

## 3. Adopt Anthropic's loop taxonomy in `skills/run-loop/SKILL.md`

**Source:** [Loop engineering: Getting started with loops — claude.com/blog, 2026-07-07](https://claude.com/blog/getting-started-with-loops) — the official Claude Code team's four-loop taxonomy: turn-based / goal-based / time-based / proactive.

### Why it's relevant
The harness's `run-loop` SKILL already opens with an explicit disambiguation:

> Name chosen over `/loop` — that is the Anthropic interval-scheduler built-in. `/run-loop` is consistent with `/run-wave`.

That disambiguator was written before Anthropic published a formal taxonomy. As of 2026-07-07 the taxonomy is:

1. **Turn-based loops** — one prompt, agent iterates internally until it judges the task done. (Corresponds to normal Claude Code use.)
2. **Goal-based loops** — `/goal` runs until a separate judge model verifies success. Stops on its own.
3. **Time-based loops** — `/loop` runs a task on a timer while the session is open. Dies with the session.
4. **Proactive loops** — `/schedule` (called `/routine` in some places) runs as a durable cloud routine, surviving machine close.

Mapping the harness's own loops:

- **`/run-loop`** (this SKILL, plan.md waves + `ready-for-agent` issues) → **time-based, unattended, mechanical-gate variant** — closer to `/loop` than to `/goal` because it drains from an external work queue rather than judging a goal condition, but with adversarial verification per item.
- **`/planning-loop`** → **goal-based** (Codex adversarial review until acceptance criteria met).
- **`/session-start`** / **`/session-end`** → **turn-based** book-ends.
- **This anthropic-review routine** → **proactive** (cloud routine — Anthropic's own product form).

The current disambiguator ("`/run-loop` is not `/loop`") is correct but under-informative. A one-paragraph mapping upgrade would help a future reader (or future-maintainer) place `/run-loop` in the vendor taxonomy without re-deriving it.

### Concrete change
Insert a new paragraph in `skills/run-loop/SKILL.md` right after the existing disambiguation line (currently line 13), before the Status block:

```diff
 Name chosen over `/loop` — that is the Anthropic interval-scheduler built-in. `/run-loop` is consistent with `/run-wave`.

+**Where this SKILL lands in Anthropic's loop taxonomy** ([Getting started with loops, 2026-07-07](https://claude.com/blog/getting-started-with-loops)): `/run-loop` is a **time-based unattended loop** with a mechanical gate — it does not have a goal-verifying judge (goal-based) or a persistent cloud schedule (proactive). Adjacent harness loops:
+
+- `/planning-loop` — **goal-based** (adversarial review until acceptance-criteria pass)
+- `/session-start` + `/session-end` — **turn-based** book-ends around normal Claude Code use
+- The `anthropic-reviews` routine — **proactive** (runs as a Claude Code cloud routine, survives session close)
+
+If Anthropic ships a `/loop` variant that also drains a work queue with an adversarial gate, revisit whether `/run-loop` should adopt the built-in.

 > **Status (as of Wave 21 — LIVE):** the live execution path is wired.
```

Also — one line in `AGENTS.md` "Loop protocol" section (whichever line names the tool-neutral loop protocol) referencing the Anthropic taxonomy as the vocabulary the tool-neutral protocol implements.

### Expected payoff
Grounds the harness's non-trivial loop story (`/run-loop`, `/planning-loop`, `/session-start`+`/session-end`, `/schedule`-style routines) in Anthropic's canonical four-loop taxonomy. Costs one paragraph in one SKILL.md. Makes it easier to argue in a future review whether a new loop should be built here or adopted from Anthropic.

**Verify before applying:** `grep -rn "getting-started-with-loops\|Anthropic's loop taxonomy" skills/ AGENTS.md` should return no matches.
