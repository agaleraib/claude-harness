## 4. Adopt Anthropic's large-scale code-migration playbook as an optional `migration-playbook` skill

**Source:** [How Anthropic runs large-scale code migrations with Claude Code — claude.com/blog, ~mid-July 2026](https://claude.com/blog/ai-code-migration). Companion GitHub kit: [anthropics/code-migration-kit-with-claude-code](https://github.com/anthropics/code-migration-kit-with-claude-code) — prompts, templates, and scripts. Two case studies anchor the guide: Jarred Sumner's Zig-to-Rust port of Bun (~1M lines, <2 weeks, ~$165K API, 100% tests passing) and Mike Krieger's Python-to-TypeScript migration (165K lines over a weekend, "hundreds of agents, eight phase gates, three adversarial review rounds").

### Why it's relevant

The methodology maps well onto shapes the harness already has:

- **Rulebook / dependency map** phase ≈ `spec-planner` output shape.
- **Parallel translation** phase ≈ `orchestrator` fan-out.
- **Compiler / smoke-test fix loop** ≈ `run-loop` (worktree runner).
- **Adversarial review rounds** ≈ `code-reviewer` agent.
- **Parity check** ≈ `criteria/` scoring pass.

The harness already ships `skills/migration-check/SKILL.md` (a *pre-migration* check, judging by the name; verify before referencing). What the harness does **not** ship is a **playbook that composes those existing pieces into the six-phase migration flow the post lays out**. Anthropic has open-sourced the exact prompts + templates + scripts in the linked kit, which is the shortest path to a `migration-playbook` skill: vendor the kit's scripts as `skills/migration-playbook/lib/`, thread them into the existing `run-loop` and `orchestrator`.

### Why this is `defer`, not `apply`

1. **No live migration on this repo or a consumer project.** The harness's `wordwideAI` consumer isn't planned for a language migration in the current wave sequence. Building the skill without a real target is speculative.
2. **`scope: speculative`.** Per the routine's own vocabulary — new skill, new templates, cross-cuts run-loop and orchestrator, likely 5+ file additions. Substantive per the README's rule of thumb.
3. **The upstream kit is a moving target.** Vendoring it as a skill now means eating merge conflicts every time Anthropic updates prompts. Better to wait until a real migration project, then vendor the version that works and mark the skill "snapshot of `code-migration-kit-with-claude-code` at commit <sha>."
4. **Big-model dependency.** The post's cost numbers ($165K for 1M lines) assume Opus-class models with generous throughput; solo-tooling economics don't currently support that scale.

Not this run. When a real migration surfaces:

2. Vendor `anthropics/code-migration-kit-with-claude-code` (or fork) into `skills/migration-playbook/lib/`. Pin the upstream sha in `skills/migration-playbook/UPSTREAM`.

4. Consider whether to rename `migration-check` → `migration-precheck` for clarity, or fold the two under a `migration-*` namespace. Leave that decision for the spec.

### Expected payoff (when applied)
