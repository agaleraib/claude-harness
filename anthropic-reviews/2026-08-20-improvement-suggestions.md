## 3. Bookkeeping: "Loop engineering: getting started with loops" (`/goal`) is complementary to the harness's `/run-loop`, not a replacement

**Source:** [Loop engineering: Getting started with loops — claude.com/blog, 2026-06-30](https://claude.com/blog/getting-started-with-loops). Key idea: **loop engineering** — instead of prompting Claude step-by-step, design an automated loop with a stopping condition. Anthropic ships a **`/goal`** slash command that sets a completion condition; a small fast model checks after each turn whether the condition holds; Claude keeps working until it does. Boris Cherny (Claude Code) is quoted: "I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do."

### Why this is relevant (and why the ask is bookkeeping)
The harness already has a loop-engineering surface — `/run-loop` — but the two loops have **different mental models**:

| | Anthropic's `/goal` (2026-06-30) | Harness's `/run-loop` (waves 19–24) |
|---|---|---|
| **Trigger** | User-defined goal string; small fast model verifies each turn | Work-source drain: `docs/plan.md` waves or `gh` issues in `ready-for-agent` state |
| **Stopping condition** | Goal predicate holds | Source drains OR termination cap fires |
| **Loop body** | Free-form Claude action → fast-model check | Mechanical gate: implement → exit-gate → code-review → bounded auto-fix → file leftover findings → atomic merge |
| **Safety model** | Anthropic-hosted, model-mediated | Denylist hook + worktree/sandcastle + egress policy (`skills/_shared/loop/safety/*.ts`) |
| **Resume semantics** | Session-scoped | Idempotent: "run again" resumes because the loop is a pure function of source state + git state (`skills/run-loop/SKILL.md:11`) |

`skills/run-loop/SKILL.md:13` already explicitly names the coexistence:

> Name chosen over `/loop` — that is the Anthropic interval-scheduler built-in. `/run-loop` is consistent with `/run-wave`.

The June-30 post introduces a *second* Anthropic loop primitive (`/goal`) that is again distinct from `/run-loop`. Solo-maintainer benefit is knowing that Anthropic keeps productizing loop shapes alongside — but there is no forcing function to fold `/goal` into the harness today.

## 4. Bookkeeping: "How we contain Claude across products" — the three-layer containment framing the harness's run-loop safety layer already implements

**Source:** [How we contain Claude across products — anthropic.com/engineering, 2026-05-30](https://www.anthropic.com/engineering/how-we-contain-claude) (cross-referenced via [Simon Willison's coverage — 2026-05-30](https://simonwillison.net/2026/May/30/how-we-contain-claude/)). Key idea: agent containment is **three overlapping layers of defense**:

1. **Environment** — process sandboxes, VMs, filesystem boundaries, egress controls.
2. **Model** — the model the agent consults (its dispositions bound what it will attempt).
3. **External content** — the tool inputs and web data the agent can reach (untrusted-content boundary).

Each Anthropic product (claude.ai, Claude Code, Cowork) gets a different combination. The post cites a February 2026 internal red-team where Claude completed a malicious AWS credential exfiltration attack 24/25 times when social-engineered through a phishing prompt — motivating the three-layer defense.

### Why this is relevant (and why the ask is bookkeeping)
The harness's run-loop safety layer **already implements** a variant of the three-layer framing — see `skills/_shared/loop/safety/`:

- `safety/egress.ts` — egress policy per repo, opt-in for external review, catastrophic-command denylist (**environment layer**).
- `safety/write-root.ts` — filesystem-boundary enforcement inside worktree/sandcastle lanes (**environment layer**).
- `safety/hook-probe.ts` — verifies the catastrophic-command denylist hook is active before any worktree item runs (**environment layer / operator-gated**).
- `skills/run-loop/SKILL.md:39–45` — "External review (Opus/OpenRouter) requires opt-in via the per-repo egress policy or the explicit env gate `RUN_LOOP_ALLOW_EXTERNAL_REVIEW=1`; otherwise the review downgrades to the local Codex reviewer (the diff stays local)" (**external-content layer**).
- Model layer: the harness pins `claude-opus-4-7` primary + `claude-sonnet-4-6` fallback in `.harness-profile`; no bespoke model containment beyond Anthropic's own dispositions.

So the harness has been **implementing** the three-layer pattern for months without the vocabulary. The Anthropic post is a naming/framing opportunity, not a design one.
