## 3. Adopt the "dreaming" / offline memory-consolidation pattern as a `/session-end` extension

**Source:** [The components of agent memory — anthropic.com/research, 2026-11-06](https://www.anthropic.com/research/components-of-agent-memory) — Four cross-session layers: transcripts (searchable event log), memory notes (in-session scratch), memory representations (wikis, structured artifacts), injected context (small, loaded every session). Plus **dreaming**: an offline pass that reviews transcripts and notes, corrects errors, builds representations, promotes useful notes up and demotes re-derivable state down. Key quote: *"Store information that can't be re-derived from the screen or environment, such as plans and tested rules, rather than state that is always visible."* Experimentally: dreaming raised contract-term retention from 41/57 to 57/57 facts.

### Why it's relevant
The harness already has a four-layer memory model that mirrors the post's layering almost 1:1:

| Post's layer | Harness equivalent |
|---|---|
| Transcripts | Claude Code `~/.claude/projects/<cwd>/history/*.jsonl` (auto-logged) |
| Memory notes | `.harness-state/today_goal.md`, `.harness-state/last_exit.md`, `.harness-state/current_micro.md` |
| Memory representations | `~/.claude/memory/feedback/<slug>.md` (promoted patterns) |
| Injected context | `~/.claude/memory/FEEDBACK.md` (≤5KB cap, loaded at session start) |

**What's missing is the dreaming pass.** Today, promotion from per-cwd auto-memory into `~/.claude/memory/feedback/` is **manual** via `/memory-prune` (CLAUDE.md:14, AGENTS.md:§Memory). The post's finding — that dreaming catches re-derivable notes polluting the top layer, and that `global.md` should be a tight dashboard not a dump — is exactly the drift `/memory-prune` was designed to reverse, but there's no scheduled or session-end trigger that even flags the question.

Two sub-ideas worth noting even if the overall § is deferred:

1. **Test notes against transcripts.** The post says *"Dreaming gives Claude a way to test its notes against the original transcripts."* The harness has transcripts (Claude Code's auto-log) and notes (`.harness-state/`); nothing cross-references them.
2. **One writer per entity.** The post: *"Give each entity its own page, written by one agent, to avoid overwrites from concurrent writers."* FEEDBACK.md's 5KB cap + the `/memory-prune` writer-only convention already does this; worth documenting that the harness has been running this discipline since 2026-04.

### Concrete changes (sketch, for when the trigger lands)

**`skills/session-end/SKILL.md`** — add a new Phase after the existing exit-note writeback:

```
## Phase N: dreaming (opt-in)

If `~/.claude/projects/<encoded-cwd>/memory/MEMORY.md` has not been pruned in the last 7 days
(check `stat -c %Y` against now-604800), surface one line to the operator:

  "MEMORY.md has drifted — 14 lines added since last prune. Run `/memory-prune` to consolidate?"

Do NOT auto-prune. The operator owns shared-root mutation (AGENTS.md:§Memory).
```

**`skills/memory-prune/SKILL.md`** — add an §"Anti-pattern: re-derivable state" citing the post's finding: *"Store plans and tested rules, not state that is always visible on screen."* Lines in FEEDBACK.md that describe current directory layout, open file lists, or the current branch are candidates to demote.

### Why this is a defer, not an apply

No pain signal. The 14-char-per-line ≤150 budget already keeps FEEDBACK.md honest, and `/memory-prune` runs manually when the operator reads a stale entry. The post's pattern is the right shape — the trigger to build it hasn't fired. If FEEDBACK.md over-cap warnings start showing up in `/session-start` output more than once a month, that's the signal.

**Verify before applying:** (a) `stat -c '%y %n' ~/.claude/projects/-home-user-claude-harness/memory/MEMORY.md 2>/dev/null` — if this file's mtime is > 30 days old and `wc -l` is > 200, the pattern is relevant; (b) `grep -c '^' ~/.claude/memory/FEEDBACK.md` — if over the ≤5KB / ~150-line soft cap, the trigger has fired.

**Recommended verdict:** defer until auto-memory shows re-derivable notes polluting FEEDBACK.md

## 4. Harden the global PreToolUse denylist hook with symlink-resolution + explicit `loop_allowlist` default

**Source:** [How we contain Claude across products — anthropic.com/research, 2026-05-25](https://www.anthropic.com/research/how-we-contain-claude) — Three key findings for this repo: (a) the "approve-every-action" model led to 93% approval rate (fatigue); the OS-level sandbox cut prompts by 84% while enforcing default-deny network. (b) Two real incidents involved symlinks inside allowed folders pointing outside them, and exfiltration through allowlisted domains. (c) *"Resolve symlinks before path checks."* Allowlists beat denylists because a denylist can't enumerate every bypass. Project config (`.claude/settings.json`) can execute code if trusted before consent — treat untrusted repos as untrusted input.

### Why it's relevant
The loop harness has a global PreToolUse hook (`~/.claude/settings.json`) driven by `skills/_shared/loop/safety/denylist.ts`. Reading the module's own docstring (lines 1–24 of `denylist.ts`):

> CRITICAL POSTURE (spec Task 10): a string denylist cannot enumerate every bypass (alternate syntax, scripts, aliases, path variants, non-shell file tools). The hook is therefore a BACKSTOP LAYER, not the confinement boundary.

That's the exact framing the Anthropic post uses. The matcher already canonicalizes commands and honors a `loop_allowlist:` posture (lines 18–21, 34, 330–335). But two gaps match the post's two named incidents:

1. **No symlink resolution before path checks.** `grep -rn "realpath\|symlink" skills/_shared/loop/safety/` returns zero hits. The write-root confinement defers to `safety/write-root.ts`, but a symbolic link inside the worktree pointing outside it is not resolved before the path is compared against the write root. This is exactly the first incident the post describes.
2. **No shipped example `loop_allowlist`.** The matcher logs a `weak-posture` warning when `loop_allowlist` is undefined (`guardrails.ts:120`), but no file in the repo demonstrates what a reasonable allowlist looks like. The fix "we recommend allowlists over denylists" lands flat because operators see the warning and have nowhere to start.

### Concrete changes

**`skills/_shared/loop/safety/write-root.ts`** (or wherever path checks resolve) — add a `realpath(path)` pre-step before any containment check:

```typescript
// Resolve symlinks before path checks (Anthropic 2026-05-25 containment post, §incidents).
// A symlink inside an allowed folder can point outside it; never match a raw path.
const resolved = await fs.realpath(candidatePath);
if (!resolved.startsWith(worktreeRoot)) {
  return { action: 'block', rule: 'symlink-escape', reason: `${candidatePath} → ${resolved} outside worktree root` };
}
```

(The exact seam is whichever function compares file paths to `worktreeRoot`. A test case should include a symlink at `<worktree>/outlink → /etc/passwd` and assert `block`.)

**`skills/_shared/loop/safety/README.md`** (or inline in `denylist.ts` header comment) — ship a documented default `loop_allowlist` block the operator can copy into `.harness-profile`:

```yaml
loop_allowlist:
  # Read-only inspection
  - "ls "
  - "cat "
  - "grep "
  - "rg "
  - "git status"
  - "git log"
  - "git diff"
  # Build/test (project-specific; override per repo)
  - "npm test"
  - "node --test"
  # Explicit write ops
  - "git add "
  - "git commit "
```

Each entry is a prefix — `grep -n "allowlist.some" denylist.ts` confirms prefix-match semantics.

**README (or `skills/_shared/loop/safety/README.md` once written)** — one paragraph citing the Anthropic post's framing: *"Allowlists beat denylists because a denylist can't enumerate every bypass; the denylist in this harness is a backstop, not the confinement boundary."*

### Expected payoff

- **Closes a real bypass.** A symlink attack on the worktree confinement is a documented Anthropic incident; the harness today permits it.
- **Makes allowlist-leaning posture actionable.** Operators see the `weak-posture: no loop_allowlist declared` warning but have nowhere to copy from. A shipped example removes the friction.
- **Cites the authority.** The post's "backstop, not boundary" framing is already the harness's posture; promoting that from a buried comment to a doc paragraph protects it from drift.
