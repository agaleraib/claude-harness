## 3. Add @-mention-files + set-model/effort-before-starting rows to the README Session Hygiene table

**Source:** [Maximizing the value of your Claude Code sessions — claude.com/blog, 2026-08-14](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions) (Lydia Hallie). Seven tips from Anthropic's own engineers on getting the most value from every Claude Code session. Two of them are directly missing from the harness's existing **Session Hygiene** table (`README.md:848–869`):

- **Set model and effort level BEFORE the session starts** — changing either mid-conversation busts the prompt cache and re-pays the whole session's input tokens; the harness already has the `orchestrator` agent doing model routing but doesn't tell the human user this cache-preservation rule.
- **@-mention files instead of naming them** — `@path/to/file.ts` attaches the file to the message directly, saving Claude a Read call (or a search if it has to go find the file). This is a concrete cache-and-context savings that generalizes across every session, not just orchestrator-mediated ones.

The post also reiterates several practices the harness already has (`/clear` between tasks, subagents for verbose work, running noisy commands with quiet flags or in subagents), so those don't need repeating.

**Grep confirms neither tip is already in the table:**
- `grep -n "@-mention\|@ file\|@mention" README.md` → 0 hits.
- `grep -n "effort level\|set effort\|effort before" README.md` → 0 hits.

### Concrete change
**Two rows added to the existing Session Hygiene practices table** in `README.md:862–869`:

```diff
 | Practice | When | Why |
 |---|---|---|
 | **`/clear` between tasks** | After finishing a feature, before starting something unrelated | Resets context completely. Single biggest quality improvement. |
 | **`/compact Focus on [X]`** | When you can't clear but context is growing | Summarizes old context while preserving what matters. |
 | **Two corrections → `/clear`** | After correcting Claude twice on the same issue | Failed approaches pollute context. Start fresh with a better prompt that includes what you learned. |
 | **`/rename` your sessions** | When starting meaningful work | `claude --resume` shows session names. "oauth-migration" beats "session-47". |
 | **Use subagents for research** | When Claude needs to read many files | Research in a subagent returns a summary. Direct exploration fills YOUR context with file contents. |
 | **`/btw` for side questions** | Quick questions mid-task | Answer appears in overlay, never enters conversation history. Zero context cost. |
+| **Set model + effort BEFORE the session starts** | Before your first prompt of a session | Changing either mid-conversation busts the prompt cache and re-pays the whole session's input tokens ([Aug 14 tips post](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)). |
+| **`@path/to/file` instead of naming files in prose** | Whenever you already know the file path | The file attaches directly to your message — saves one Read tool call, or a search if Claude has to locate the file. |
```

### Expected payoff
Two concrete, cache-preserving, per-session cost savings the maintainer (and future harness users) can adopt without touching a single skill or agent. Both are behavioral, not architectural — pure documentation, zero-code — and both come from Anthropic's own engineers on the Claude Code team. Reinforces the harness's "we track first-party best practices" positioning.

## 4. Adopt `claude doctor` as a periodic audit ritual for CLAUDE.md + skills

**Source:** [The new rules of context engineering for Claude 5 generation models — claude.com/blog, 2026-07-24](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) — announces a new **`claude doctor`** CLI command that helps developers rightsize their own `CLAUDE.md` files, skills, and other user-authored context to the Claude 5 tier's default judgement (i.e. the "unhobbling" cited in §1 applied to the user's own harness, not just Anthropic's).

### Why it's relevant
The harness has three existing entrypoints where auditing user-authored context matters:

- `skills/memory-prune/SKILL.md` — already handles the `~/.claude/memory/` and per-cwd MEMORY.md audit + hand-promotion flow. Complementary but different scope: `memory-prune` audits *memory*, `claude doctor` audits *skills + CLAUDE.md*.
- `skills/apply-anthropic-reviews/SKILL.md` — the maintainer-facing skill that decomposes and applies suggestions from this file. A "before-you-apply" step running `claude doctor` on the current CLAUDE.md would surface unnecessary constraints proactively.
- `AGENTS.md` §"What to avoid" bullet on prefix stability (line 54) — already argues against baking dynamic content into static prompt files for cache-invalidation reasons. `claude doctor` extends the same audit lens to whether *static* content is even still needed.

**However**, `claude doctor` is not listed among this session's available skills (grep of the system prompt returns 0 hits), the July 24 post frames it as "shipping" without a version number, and Claude Code CLI features often go through a research-preview → beta → GA arc. The harness principle is not to bake in dependencies on features that haven't stabilized — see the 2026-04-19 §3 deferrals of Managed Agents adoption for the same pattern.

### Concrete change (deferred — sketch only)
When `claude doctor` reaches GA (visible in the standard Claude Code CLI, documented on code.claude.com, no experimental-beta flag required):

1. Add a **"Preflight: run `claude doctor` on user-authored context"** section to `skills/apply-anthropic-reviews/SKILL.md`, invoked before the decompose-and-batch step. Purpose: catch cases where a suggestion would add a constraint that the current model no longer needs.
2. Add a paragraph to `AGENTS.md` §"What to avoid" (or a new §"Periodic audits") pointing users at `claude doctor` for their own harness / project `CLAUDE.md`, with a suggested cadence (e.g. "every model-tier upgrade, or every N `/apply-anthropic-reviews` batches").
3. Consider a new `/audit-context` skill that wraps `claude doctor` + `memory-prune` + a diff summary of what would change. Only pursue if the wrapping adds value beyond invoking the two directly — otherwise deprecate.

### Expected payoff
Catches the drift where the harness's minimalism thesis (§1 evidence) is undermined by user-added constraints in project-local CLAUDE.md files. `memory-prune` already covers the memory-directory side; this closes the loop for the skills + CLAUDE.md side. Deferred because the tool isn't yet stable enough to build a ritual around.

### Verify before applying
