## 4. Migrate the anthropic-reviews routine to a dynamic Workflow script

**Source:** [A harness for every task: dynamic workflows in Claude Code — claude.com/blog, 2026-06-02](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code). Anthropic shipped the `Workflow` tool: a JavaScript scripting layer that spawns sub-agents via `agent(prompt, opts)`, coordinates them with `parallel(thunks)` / `pipeline(items, stage1, stage2, …)` / `phase(title)`, and returns their outputs directly to the script. Every workflow's script auto-persists to disk and is resumable via `Workflow({scriptPath, resumeFromRunId})`.

### Why it's relevant
This routine — the very anthropic-reviews prompt the maintainer runs — is a natural fit for the dynamic-workflow shape:

1. **Discovery** — one WebSearch pass produces the candidate list (sequential, ~1 turn).
2. **Grep the repo for existing coverage** — currently done serially inside the main session, one `Grep` at a time (~4-6 turns for a 15-candidate window). A `parallel(candidates.map(c => () => agent(`grep for coverage of "${c.title}"`, {label: c.slug, schema: COVERAGE_SCHEMA})))` fan-out would do this in one turn.
3. **Draft §s** — per-candidate `agent(draftPrompt(c), {schema: SECTION_SCHEMA})` in a `pipeline(candidates, gather, draft)` shape.
4. **Assemble** — a final synthesis turn to build the triage summary + write the file (this stays in the main session).

The 2026-05-10 §2 ("Migrate to a Claude Code Cloud Routine") tracked the **scheduling** side of this — how the prompt fires — and deferred pending cost/pain. This § is the orthogonal **execution** side: how the prompt itself runs *within* a Claude Code session, once fired. The two suggestions can compose independently.

The workflow shape also gives resumability, which matters for a routine that reads 15 web pages: a mid-run WebSearch failure today wastes the whole turn; a Workflow can resume from the last successful stage via `{scriptPath, resumeFromRunId}`.

### Why this is `defer`, not `apply` or `spec`

Two honest reasons to leave this on the shelf for now:

1. **The routine is not the bottleneck.** This 2026-08-13 run's sequential grep + draft ran to completion inside a normal Claude Code session with no context-window pressure. Anthropic's own guidance for dynamic workflows names the trigger criteria as: *"Workflows pay off precisely when the task is too big, too parallel, or too prone to self-grading for one context window to handle."* The anthropic-reviews routine is currently none of these — a 15-candidate window fits comfortably in one context and the drafts don't need adversarial verification. Applying the pattern now is speculative optimization.

2. **The routine's per-candidate scoring is inherently sequential.** The triage summary at the top of every dated file requires knowing all the §s before ordering them. That's a synthesis step that fights the fan-out shape — a `parallel()` of drafts would return `{§1, §2, §3, §4}` but the maintainer wants them ordered by leverage, not by discovery order. Workflows *can* express this (a `parallel()` for drafts followed by a synthesis agent) but the added machinery buys little when the sequential version already produces a well-ordered triage table.

Scope: speculative — matches Anthropic's own "*when the task is too big, too parallel, or too prone to self-grading*" trigger, and this routine isn't there yet.

### Concrete change (deferred)

None this run. When the maintainer takes this on — likely when the routine's typical run exceeds ~30 min wall-clock or exhausts context — the smallest viable script:

```javascript
export const meta = {
  name: 'anthropic-reviews-routine',
  description: 'Weekly Anthropic post review — fan out grep + draft per candidate',
  phases: [{ title: 'Discover' }, { title: 'Coverage' }, { title: 'Draft' }, { title: 'Synthesize' }],
}

phase('Discover')
const candidates = await agent('Search Anthropic sources for posts since the last tracker entry; return list.', {schema: CANDIDATE_LIST_SCHEMA})

const drafts = await pipeline(
  candidates.posts,
  c => agent(`Grep the harness repo for existing coverage of: ${c.title} (${c.url})`, {phase: 'Coverage', schema: COVERAGE_SCHEMA}),
  (coverage, c) => agent(`Draft a suggestion § for ${c.title}. Coverage-check found: ${JSON.stringify(coverage)}`, {phase: 'Draft', schema: SECTION_SCHEMA})
)

phase('Synthesize')
return { candidates, drafts }
```

The main session then assembles the triage table and writes the dated file.

### Expected payoff (when applied)
- Grep coverage becomes O(1) turns instead of O(N).
- Mid-run failures resumable via `{scriptPath, resumeFromRunId}`.
- The routine's script itself becomes a **reference implementation** for dynamic workflows the harness can point consumer projects at when they ask "when should I use `Workflow`?" — turning the routine into its own case study.
